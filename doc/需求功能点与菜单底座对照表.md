### 3.2 排障工作台 `/diagnosis`（✅ #4）

代表文件：`platform/frontend/src/pages/Diagnosis.tsx`、`platform/backend/internal/diagnose/engine.go`

- 双视角发起：按"应用 appId"或按"中间件类型 + 地址"，可选症状、环境、视图口径（folded / expanded）；
- **拓扑能力三层融合**（2026-10-28 新增）：
  - 发起层：中间件候选下拉（`/api/topo/op/mwTargets`，按类型分组、附依赖应用数，实测 341 个候选）；支持 `?appId=` / `?mwType=&addr=&env=` URL 参数预填，可从运维关系拓扑一键带入；"预览该中间件影响的应用"虚线按钮在发起前即可反向查询；
  - 证据层：证据链第一步（`tool=impact`）内嵌 `ImpactCard`——中间件级展示完整反向查询应用表（每行可「从此应用排障」），应用级展示依赖中间件 Tag（每个可跳转排障），并提供「查看完整拓扑」「去影响面分析」出口；
  - 联动层：与 `/op-topology` 双向跳转（拓扑节点 → 发起排障；排障 → 完整拓扑）；
- 固定流水线（M1–M5，10–11 步 / 12 个工具调用点）：①拓扑影响面 → ② Prometheus 发现（`list_alerts` + `up`） → ③ 数据源验真（`healthy` / `targets_metadata` / `series` / `get_shards`，写 `sourceHealth` 不建步骤） → ④ CMDB 归属与问题单（`DiagnosisTicket`） → ⑤ Pinpoint 定位（`list_applications_tool` + `get_server_map_tool`） → ⑥ 指标基线（`range_query`） → ⑦ 热力图取 traceId → ⑧ 单笔调用链定因（非根 span ≥50%） → ⑨ 日志取证（ES `search` 优先，失败回退 `log_analyzer`）；
- **候选打分**：`候选置信度 = 基础置信度 × 规则强度系数`（早期固定权重已废弃）。基础置信度由第 4 步取证产出的证据集推导：

  ```text
  base = min(0.9, 0.25 + 0.10 × 证据来源数 + 0.02 × min(证据条数, 10))
  ```

  证据来源为 `topo` / `pinpoint` / `promthus`（告警 + 指标）/ `log` / `cmdb` / `rule` 六类，同一来源的多条证据累加为条数（条数最多计 10 条）；无任何有效证据时 `base = 0.2`；结果 `round2` 保留两位小数。

  **规则强度系数表**（`internal/diagnose/engine.go` `rank`）：

  | 根因候选规则 | 强度系数 |
  |---|---|
  | 共享中间件爆炸半径过大（影响应用数 ≥ `EXPLOSION_THRESHOLD`） | 1.0 |
  | 调用链单 span 占比 ≥50%（瓶颈集中） | 1.0 |
  | CMDB 已非在线且无监控心跳（实例已下线仍被依赖） | 1.0 |
  | 存在与目标相关的活跃告警 | 0.95 |
  | 日志错误激增 | 0.85 |
  | CMDB 状态过期（台账非在线但仍有心跳） | 0.85 |
  | 主机负载持续劣化（`node_load1` 观测窗内上升 >30%） | 0.8 |
  | 应用仅依赖单一中间件实例（无旁路） | 0.7 |
  | 依赖实例未纳入 CMDB（账实不符） | 0.7 |
  | 影响面收敛（依赖应用 <3，更像应用侧问题） | 0.6 |
  | Pinpoint 未覆盖（调用链证据缺失） | 0.45 |
  | 兜底「证据不足，需人工补充」 | 0.35 |

- **三道强制降权（防假阳性）**：① 无任何有效证据（`sourceCount==0`）时所有候选压到 ≤0.2，根因固定为「证据不足，暂无法定因（疑似）」；② 弱证据（拓扑影响面为空且 Pinpoint 未匹配）时最高候选 ≥0.6 一律压到 0.5；③ 数据源验真未通过（`sourceHealth` 为 `degraded` / `unavailable`）时全部候选 >0.5 一律封顶 0.5；
- **会话级结论与下游**：`session.confidence = 最高候选置信度`；状态机 `sourceCount==0 → no_data`、`confidence ≥0.6 → root_caused`、其余 `investigating`；工单准入为有候选且置信度 ≥0.3，优先级映射 ≥0.8→P0 / ≥0.6→P1 / ≥0.4→P2 / 其余 P3；
- SSE 增量推送（300ms tick，最长 3 分钟，事件 `step` / `session` / `done` / `timeout` / `error`）；
- 每一步 args/result 落盘，历史会话 8s 刷新，前端可展开证据 JSON；
- **工单联动**（2026-10-28 新增）：会话 `root_caused` 或（有候选且置信度 ≥0.3）时由工单引擎幂等自动生成隐患工单（见 3.9），置信度映射 P0–P3 优先级；
- **日志证据已接入**（2026-11-03，2026-11-06 升级）：证据链第 10 步优先调用 ES `search`（按候选主机拼 `query_string`），ES 不可用时回退日志分析服务 `process-from-path` + 任务轮询，产出错误日志 TopN / 关键问题 / 异常模式；日志路径可由请求 `logPath` 指定或按 `LOG_PATH_TEMPLATE` 推导；两者皆不可用时该步 `skipped` 并记录原因，不阻断排障。

边界：任务书「智能排障」中唯一真正落地的一环，且**只到"根因候选"为止**，未到"定位确认"与"处置恢复"。

### 3.11 资源稽核 `/audit`（🟧 #17，2026-10-28 新增，CMDB 接入）

代表文件：`platform/frontend/src/pages/Audit.tsx`、`platform/backend/internal/audit/engine.go`、`platform/backend/internal/api/audit_handler.go`

- **CMDB 接入**：cmdb-mcp-server 注册为统一网关的独立服务（`CMDB_MCP_URL`，默认 `:8061/mcp`；2026-11-06 增 ES 后共四个上游），稽核引擎经 `mcp.Gateway.Call(ctx, "cmdb", "cmdb_server_query", {ip})` 拉取资产记录；
- **四类稽核检查**（AuditFinding `AUDIT_C1`–`AUDIT_C4`）：
  - C1 存在性：topo 中间件 host ↔ CMDB 资产账实比对（IP/逗号分隔/VIP/publicIp 多策略匹配）；
  - C2 状态一致性：CMDB `state=0` 在线核验；
  - C3 反向孤儿：CMDB 在线资产未被拓扑引用（抽样 20 条）；
  - C4 指标佐证：prometheus-mcp `up{instance=~"host.*"}` 判资产真实存活；
- **结论四态**对齐巡检口径：RISK / PASS / NO_DATA / NOT_APPLICABLE，发现项带 severity（P0–P3）与 evidence；
- **规模控制**：按依赖应用数排序取 TopN 主机，避免全量扫描；
- **单主机定向稽核（2026-11-09）**：`POST /api/audit/run` 支持 `host` 多值白名单参数（`c.QueryArray("host")`），拓扑节点「跑稽核」即按该节点主机定向；白名单模式下 C3 反向孤儿跳过全量抽样并返回 `NOT_APPLICABLE`，避免单 host 场景误报；
- 前端：运行表单（日期/环境/TopN）+ 运行列表 + RunDrawer（统计卡片 + 发现项明细表）；发现项卡片提供「开排障」，携带 `mwType / addr / env / symptom` 跳转排障工作台，C3 孤儿类发现项按钮置灰（无实例地址）。

实测（mock 资产数据）：单批 780ms，12 项发现（8×C1 P1 账实不符 + 4×C3 P3 待纳管）。2026-11-10 端到端复测：全量稽核 21 项 / 14 风险；单 host 定向稽核 3 项 / 2 风险（C3 返回 NOT_APPLICABLE）。

边界：质量评分、稽核趋势看板、报告导出仍规划；CMDB 写侧修正依赖 `/relations` 关系修正能力。

### 3.12 日志分析 `/log-analysis`（✅ 2026-10-29 新增，iframe 接入外部服务）

代表文件：`platform/frontend/src/pages/LogAnalysis.tsx`；外部服务 `log/log_analyzer`（Python FastAPI，v2.8.0）

- **接入方式**：iframe 快速验证模式——页面顶部卡片展示服务地址（前端默认 `http://localhost:8000`，可用 `VITE_LOG_ANALYZER_URL` 覆盖）+「重新加载」+「新窗口打开」，下方满屏 iframe 嵌入日志分析系统自身前端；
- **外部服务能力**（已随 iframe 一并可用）：服务器路径读取（白名单 `/var/log` `/tmp` `/home` `/Users`）与文件上传双入口、分块流式分析（checkpoint 断点续跑）、SSE 实时进度与内容推送、规则模式/LLM 模式、历史报告（按 `X-User-Id` 隔离）、PDF/Word/Markdown 报告、PCAP 分析；
- **不采用上游接口封装的原因**：日志分析是长任务（大文件数分钟）+ SSE 流式，而统一接入网关为 8s 同步超时且无流式透传能力，硬套必然超时；
- **实测**：浏览器验证通过——菜单选中、标题正确、iframe 内正常渲染「Log Analyzer Agent」界面（上传/历史报告 Tab、文件拖放区），无 `X-Frame-Options` / CSP 拦截，`/api/health` 返回 `{"status":"ok"}`；
- **运行注意**：`log_analyzer` 单独启动（`PYTHONPATH=. venv/bin/python -m uvicorn log_analyzer.web.app:app --port 8000`），首次依赖导入约 4 分钟才监听，需以 `/api/health` 判定就绪；**后端排障证据链不走页面地址**，而是读 `LOG_ANALYZER_URL`（compose 默认 `http://host.docker.internal:8020`，因本机 8000 常被 prometheus-mcp-server 占用）。

边界：当前是**并列菜单**，日志错误聚合已作为排障第 10 步证据（ES `search` 优先，失败回退 `POST /api/process-from-path` + 轮询 `/api/task/{id}`）并入 SSE 证据链；服务不可用时降级为 `skipped`，不阻断结论。

```go
func (s *Server) alertsList(c *gin.Context) {
    body, err := s.mcp.Call("prometheus-mcp", "list_alerts", map[string]any{"active": true})
    if err != nil { fail(c, 502, err); return }
    alerts := parsePrometheusAlerts(body)      // 解包，对齐 prometheus Alert struct
    deduped := dedupByKey(alerts)               // alertname+instance+appId 哈希
    sort.Slice(deduped, ...)                    // severity → startsAt
    c.JSON(200, deduped)
}

func (s *Server) alertsStream(c *gin.Context) {
    c.Header("Content-Type", "text/event-stream")
    for {
        select {
        case <-c.Request.Context().Done(): return
        case <-time.After(15 * time.Second):
            body, _ := s.mcp.Call("prometheus-mcp", "list_alerts", ...)
            for _, a := range parsePrometheusAlerts(body) {
                c.SSEvent("alert", a)
            }
            c.SSEvent("heartbeat", time.Now().Unix())
            c.Writer.Flush()
        }
    }
}

func (s *Server) alertsRoute(c *gin.Context) {
    key := c.Param("key")
    alert := lookupAlertByKey(key)
    ses, err := s.diagnose.CreateDiagnosis(domain.DiagnosisInput{
        AppId:        alert.Labels["appId"],
        MiddlewareType: alert.Labels["mwType"],
        Addr:         alert.Labels["host"],
        Symptom:      fmt.Sprintf("[自动] %s: %s", alert.Annotations["summary"], alert.Annotations["description"]),
        Env:          alert.Labels["env"],
    })
    if err != nil { fail(c, 500, err); return }
    c.JSON(200, gin.H{"sessionId": ses.ID})
}
```

```go
// internal/degradation/linear.go
func LinearSlope(series []domain.Point) float64 {
    n := float64(len(series))
    if n < 4 { return 0 }
    var sumX, sumY, sumXY, sumX2 float64
    for _, p := range series {
        sumX += float64(p.Ts)
        sumY += float64(p.Value)
        sumXY += float64(p.Ts) * float64(p.Value)
        sumX2 += float64(p.Ts) * float64(p.Ts)
    }
    denom := n*sumX2 - sumX*sumX
    if denom == 0 { return 0 }
    return (n*sumXY - sumX*sumY) / denom
}

// 斜率阈值：错误率+0.05/min、CPU+0.1%/min、内存+0.2%/min、up-0.5/min
var threshold = map[string]float64{
    "error_rate": 0.05,
    "cpu":        0.1,
    "memory":     0.2,
    "up":        -0.5,
}

func (s *Server) degradationSweep(c *gin.Context) {
    apps, _ := s.topo.Apps()         // 已有接口
    var hotspots []domain.Hotspot
    for _, app := range apps {
        for metric, thr := range threshold {
            // 调用 prometheus-mcp range_query 拉 1h 时序
            body, _ := s.mcp.Call("prometheus-mcp", "range_query", promQL(app.AppId, metric))
            series := parsePrometheusSeries(body)
            slope := LinearSlope(series)
            if slope >= thr {
                // 圈定影响面：复用 topo impact 计算
                imp, _ := s.topo.ImpactByApp(app.AppId, "expanded")
                hotspots = append(hotspots, domain.Hotspot{
                    AppId: app.AppId, Metric: metric, Slope: slope,
                    ImpactApps: len(imp.Apps), ImpactMiddlewares: len(imp.Middlewares),
                })
            }
        }
    }
    sort.Slice(hotspots, func(i,j int) bool { return abs(hotspots[i].Slope) > abs(hotspots[j].Slope) })
    c.JSON(200, hotspots)
}
```

**预估代码量**：后端约 400 行（斜率计算 + sweep + 影响面圈定 + 热点存储 + 升级路由），前端约 200 行（热点列表 + 迷你图 + 影响面弹窗）。

```go
    imp, _ := topo.ImpactByApp(target.AppId, "expanded")
    // 爆炸半径权重
    score += float64(imp.TotalApps) / 200 * 0.4
    if imp.TotalApps >= 10 { blockers = append(blockers, "影响应用 ≥ 10，请人工审批") }
    // 快照漂移权重
    diff, _ := topo.Diff(target.DatePrev, target.DateToday)

    // 历史故障权重（排障会话按 appId 聚合）

    return score, blockers
}
```

```go
func CompareBaseline(before, after domain.Baseline) (degraded []string, ok bool) {
    for _, metric := range []string{"throughput", "error_rate", "cpu", "memory", "p99_latency"} {
        b := before.Values[metric]
        a := after.Values[metric]
        if b == 0 { continue }
        ratio := (a - b) / b
        if metric == "error_rate" || metric == "p99_latency" {
            if ratio >= 0.2 { degraded = append(degraded, metric); continue } // 越高越差
        } else if ratio <= -0.2 {
            degraded = append(degraded, metric) // 越低越差（吞吐量）
        }
    }
    return degraded, len(degraded) == 0
}
```

```go
func AuditSnapshot(rows []domain.TopoRow, dates []string) domain.AuditResult {
    var (
        rowScore  float64 = 100                    // 行数分
        fieldScore float64 = 100                   // 字段完整度分
        anomalies []string
    )
    mean := rollingMean(rows, dates, 3)          // 近 3 天均值
    if len(rows) == 0 {
        rowScore = 0; anomalies = append(anomalies, "快照行数为 0")
    } else if float64(len(rows)) < mean*0.8 {
        rowScore = 60
        anomalies = append(anomalies, fmt.Sprintf("行数较近 3 天均值下降 %.0f%%", (mean-float64(len(rows)))/mean*100))
    }
    missing := fieldMissingRatio(rows, ["apolloAppId", "middlewareType", "connectAddr", "apolloHostId"])
    fieldScore -= missing * 50
    if missing > 0.1 { anomalies = append(anomalies, fmt.Sprintf("字段缺失率 %.0f%%", missing*100)) }
    return domain.AuditResult{Score: (rowScore+fieldScore)/2, RowScore: rowScore, FieldScore: fieldScore, Anomalies: anomalies}
}
```

### A.13 数据预处理 `/preprocess`（prometheus 指标前置处理）

**内置处理规则**

1. **缺失值线性插值**：窗口内连续 NaN ≤ 5 点时前后值插值
2. **异常值 3σ 剔除**：点与窗口均值差 > 3σ 时替换为均值
3. **滑动窗口聚合**：输入原始 1m 粒度，输出 5m / 15m 粒度均值 / 最大 / 最小
4. **差分**：对时序做一阶差分，突出趋势变化

**上游接口调用改造**：prometheus-mcp 调用返回原始时序后，自动加载已配置的处理规则链（`engine.McpTools.Call` 末尾加 `ApplyPipeline` 钩子），返回清洗后数据。

**前端步骤**

1. 规则注册中心：4 个内置规则 + 参数表单（窗口大小 / 插值阈值 / σ 倍数）
2. 规则链编排：拖拽式选择规则 + 顺序 + 参数，保存为 pipeline
3. 实时预览：原始折线 + 清洗后折线叠加对比

**预估代码量**：后端约 300 行（4 个处理函数 + pipeline Hook 接入），前端约 250 行（规则表单 + 链编排 + 叠加预览）。
