## 一、总量与排序原则

| 档位 | 项数 | 含义 |
|---|---|---|
| P0 | 4 | 先闭环：做出可演示的端到端价值 + 交付阻塞底座 |
| P1 | 5 | 再执行：执行通道、编排、度量、交付 |
| P2 | 2 | 后平台化：数据与算法、通用能力余项 |

排序原则：**先闭环（验证半边 + 底座）→ 再执行（执行通道 / 编排 / 指标 / 交付）→ 后平台化（数据与算法）**。

---

## 二、P0：先闭环（4 项）

| 事项 | 对应条目 | 依赖 / 可复用底座 | 完成判据 |
|---|---|---|---|
| 变更「验证半边」：拨测 + 前后基线 diff + 报告 | #14 / A.9 | topo 影响面 + 爆炸半径 + Diff、变更风险 blockers；Prometheus 拨测 | 一次变更产出前后对比报告；关键指标 diff ≥20% 自动标红并阻断「完成」 |
| 巡检 RISK → 处置建议 + 一键建单 | #10 | 巡检四态 RISK、工单引擎 | 一批 RISK 100% 产出建议；一键建单幂等、不重复建单 |
| 图表化报告（巡检 / 质差 / 割接同版式） | #9 | 现有报告落库 | 三类报告可导出统一版式 |
| 鉴权 / 租户中间件 + OpenAPI 目录（底座） | 通用能力 | 现有 `/api/*` 与身份表 | 全部接口需 Token；租户可过滤；OpenAPI 可枚举 |

## 三、P1：再执行（5 项）

| 事项 | 对应条目 | 依赖 / 可复用底座 | 完成判据 |
|---|---|---|---|
| 执行通道闭环：dry-run → 白名单动作 → 审批 → 回执 → 回滚 | #5 #10 #14 #18 / A.11 | 受控执行通道（SSH 跳板 / Ansible）+ 审计日志 | 一次变更或处置可端到端执行并回滚；关系修正可回写 topo/CMDB 且可回滚 |
| 排障流程编排（模板驱动） | #6 / A.5 | 现有 10–11 步证据链 + SSE | 同一 appId 用两套模板跑出不同步骤序列；模板改版后旧会话可回看 |
| 质量评分与趋势、MTTR、处置率 | #31 #33（质差 #19） | 告警 / 工单 / 稽核数据 | 指标可下钻到明细；MTTR 与处置率有趋势对比 |
| 执行侧其余：脚本下发、失败告警、RISK → 自动处置 | #10 #14 #18 | P1 执行通道 | 巡检失败可告警；RISK 可自动转工单/处置 |
| 交付化：容器化部署、运维手册、演示与验收材料 | 阶段八 | P0 底座 + 上述能力 | 一键部署；验收材料齐套 |

|---|---|---|---|

## 五、关键闸口与依赖

| 闸口 | 挡住哪些事项 | 说明 |
|---|---|---|
| 受控执行通道（SSH 跳板 / Ansible）+ 动作白名单 + 审批 + 回滚 | P1 全组（#5 #10 #14 #18 #34） | 唯一贯穿 P1 的硬前置；先 dry-run，再放写 |
| 离线批处理底座（队列/调度 + 产物目录 + 重跑幂等） | P2 数据算法全链 | 不与执行侧抢资源 |
| 鉴权 / 租户 / OpenAPI | 交付化（P1） | 属交付阻塞，故上调 P0 |
| 生产环境 Alertmanager 读权限、webhook 出网策略 | 告警闭环运维 | 已完成部分依赖此条件 |
| 业务方参与根因标注 | 质量评分 / 准确率 | 影响度量类判据 |
