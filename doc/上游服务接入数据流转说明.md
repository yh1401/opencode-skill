## 0. 术语与判态

| 术语 | 含义 |
|---|---|
| 上游 | 数据提供方：Pinpoint / Prometheus(+Alertmanager) / CMDB / ES，或平台内部产出键（拓扑、身份表） |
| 下游 | 数据消费方：落盘集合、规则判定、接口响应、前端页面 |
| 硬门禁 | 不满足则**不允许**发起调用或不允许流转，必须显式判态 |
| 软条件 | 不满足只降低置信度，流程继续 |
| 判态 | `NOT_TRIGGERED` / `RISK` / `NO_DATA` / `NOT_APPLICABLE`；优先级 `NO_DATA > RISK > NOT_TRIGGERED` |
| DF-nn | 数据流编号，用于跨文档引用 |

## 2. 统一接入层契约

### 2.1 调用壳（A1 A2 A5）

| 项 | 契约 |
|---|---|
| 签名 | `Gateway.Call(ctx, server, tool, args) (json.RawMessage, error)` |
| 注册名 | `pinpoint` / `prometheus` / `cmdb` / `es`（仅这四个） |
| 传输 | streamable HTTP（MCP 协议），端点 `.../mcp` |
| 超时 | 单次 `context.WithTimeout(MCP_TIMEOUT_MS=8000)`；巡检批次 `INSPECT_MCP_TIMEOUT_MS=5000` |
| 名单 | 先 deny 后 allow；deny 命中即 `tool denied`；生产 `MCP_ALLOW_TOOLS` 按服务收敛 |
| 审计 | `CallLog{Server,Tool,Args,OK,Error,LatencyMs,At}` → `GET /api/mcp/logs` |
| 截断 | `Result.Preview(4096)`，超限标 `truncated:true` |

**硬约束**：业务模块禁止直连 HTTP；新增工具必须先在本文补齐"五段式"（上游条件 / 请求 / 响应 / 映射 / 断裂判态）。

### 2.2 三种返回形态归一（A3）

| 形态 | 特征 | 归一 |
|---|---|---|
| 上游返回信封 | `{content:[{type:"text",text}],isError}` | `mcp.ResultOf` → `{Text,Payload,IsError}` |
| 裸业务 JSON | 直接对象/数组 | `mcp.ContentJSON` → `[]byte` |
| 文本内再套 JSON | `content[0].text` 是 JSON 字符串（CMDB） | `ResultOf` → `Payload` 二次 `Unmarshal` |

**统一顺序**：`ResultOf` 判 `IsError` → 取 `Payload` → 服务专用解析 → 失败转 `NO_DATA` 并保留 `preview`。

### 2.3 字段口径（A4 F1 F2）

| 维度 | 统一口径 | 各服务差异 |
|---|---|---|
| 时间戳 | 平台内部**毫秒** | Pinpoint 收毫秒；Prometheus `query` 返秒、`range_query` 收 RFC3339；ES 用 `now-15m` |
| 主机键 | `NormalizeHost`：去空格 → 小写 → 去 `:port` → 去尾点 | CMDB 用 `ip`；Prometheus 用 `instance`；ES 用 `host`；Pinpoint 用 `middlewares[].name` |
| 应用键 | `appId / apolloAppId / apolloAppName / pinpointAppName` | Pinpoint 只认 `applicationName` 原值 |
| 状态码 | 巡检四态 | CMDB `state` 是资产状态，不是巡检判态 |
| 空集合 | 按工具语义解释，**不默认健康** | 告警空=无活跃告警；资产空=`P1` 账实不符 |

### 2.4 失败 → 判态（A3 G3）

| 失败 | `Step.Status` | 业务判态 | 是否继续 |
|---|---|---|---|
| `connection refused` / 超时 | `error` | `NO_DATA` | 继续 |
| `unknown server` / `tool denied` | `skipped` | 数据端不可用 | 继续 |
| `isError:true` | `error` | 该步失败 | 继续 |
| JSON/文本均解析失败 | `warn` | `NO_DATA` + `preview` | 继续 |
| 空集合 | 按语义 | 见各服务 | 继续 |
| 字段缺失 | `warn` | `NO_DATA`，**不猜默认值** | 继续 |

### 2.5 幂等 / 并发 / 重试（新增，I2 H6）

| 场景 | 约定 |
|---|---|
| 排障调用 | 每个会话每工具**最多调用 1 次**，不重试；失败即 `error` |
| 巡检调用 | 批次内同一 `(server, tool, hostKey)` 只调用 1 次（`hostMCPCache`） |
| 告警入库 | 按 `fingerprint` upsert，重复推送不改事件数 |
| 超时重试 | 不自动重试；由下一轮轮询/巡检自然补偿 |
| 并发 | 巡检单协程顺序执行；跨会话并发由网关连接池控制 |

### 2.6 安全边界（新增）

| 约束 | 说明 |
|---|---|
| 只读 | 平台只消费查询类工具；`MCP_DENY_TOOLS` 必须保留 5 个写操作（`delete_series,clean_tombstones,snapshot,reload,quit`） |
| 凭据 | URL 中如带 token，不得写入 `Step.Args` / `CallLog.Args` |
| 数据出域 | 证据链只存 `Preview(4096)`；原始响应不得落盘到前端可下载路径 |
| 越权 | 多租户查询必须以 `tenantId` 过滤，工具参数中不传其他租户标识 |

## 3. Pinpoint 契约

### 3.1 上游前置条件（B1 B2）

| # | 条件 | 不满足后果 |
|---|---|---|
| P-1 | `PINPOINT_MCP_URL` 可达，Pinpoint Web/Agent 正常 | ① 直接 `skipped` |
| P-2 | 目标应用已注册采集（有 Agent 上报） | 清单命中但服务地图空窗 |
| P-3 | `service_name` 正确（默认 `DEFAULT`） | 返回空应用清单 |
| P-4 | 时间窗内存在采样 | 服务地图 `NO_DATA` |
| P-5 | 平台已完成应用三方映射 | 无法把 `appId` 翻译为 `applicationName` |

### 3.2 `list_applications_tool`（B1 B3）

**请求**

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `service_name` | string | 是 | `DEFAULT` | 项目组/服务名 |
| `clear_cache` | bool | 否 | false | 强制刷新缓存 |

**响应**

| 项 | 契约 |
|---|---|
| 路径 | `Payload` 数组，或 `{applications}` / `{applicationList}` / `{data}` |
| 必读 | `applicationName`（必）、`applicationId`（必） |
| 可选 | `serviceTypeName`、`serviceTypeCode` |
| 别名 | `applicationName\|appName\|name`、`applicationId\|appId\|id` |
| 平台结构 | `[]mcp.PinpointApplication{ID,Name,ServiceTypeCode,ServiceTypeName}` |

```json
[{"applicationName":"order-api","applicationId":"order-api^1780000000",
  "serviceTypeName":"SPRING_BOOT","serviceTypeCode":1210}]
```

**映射**

| 源字段 | 归一 | 平台字段 | 下游 |
|---|---|---|---|
| `applicationName` | 去空格；空则整条丢弃 | `.Name` | `identity_app.PinpointAppName`（DF-01） |
| `applicationId` | 去空格 | `.ID` | `identity_app.PinpointAppID` |
| `serviceTypeName` | 直取 | `.ServiceTypeName` | 排障展示 / T8 消歧 |

**下游硬依赖**：`get_server_map_tool.application_name` 只能取本工具 `Name` 原值。

**断裂判态**

| 情形 | 判态/动作 |
|---|---|
| 空数组 | `skipped`；② 记 `skipped` + "应用清单未匹配，调用链证据缺失（NO_DATA 口径）" |
| 单条缺 `applicationName` | 丢弃该条 |
| 调用失败 | `error`，不阻断 |

### 3.3 `get_server_map_tool`（B2 G1 H2）

**请求**

| 字段 | 类型 | 必填 | 默认 | 单位 |
|---|---|---|---|---|
| `application_name` | string | 是 | — | 必须为 3.2 原值 |
| `from_ts` | int | 是 | — | **Unix 毫秒（13 位）** |
| `to_ts` | int | 是 | — | **Unix 毫秒** |
| `caller_range` | int | 否 | 1 | 上游层数 |
| `callee_range` | int | 否 | 1 | 下游层数 |
| `bidirectional` | bool | 否 | true | 双向 |
| `was_only` | bool | 否 | false | 仅 WAS |
| `service_type_code` | int | 否 | — | 同名消歧 |
| `service_type_name` | string | 否 | — | 同名消歧 |

**响应**

| 路径 | 字段 | 类型 | 必读 |
|---|---|---|---|
| `nodes \| nodeData \| node_data \| applicationData` | `applicationName` | string | 是 |
| 同上 | `serviceType` / `instanceCount` | string / int | 否 |
| `middlewares` | `name` / `type` | string | 否 |
| `links \| linkData` | `from \| source \| caller` | string | 是 |
| 同上 | `to \| target \| callee` | string | 是 |
| 同上 | `count` / `errorCount` / `responseTime` | int / int / float | 否 |

```json
{"nodes":[{"applicationName":"order-api","serviceType":"SPRING_BOOT","instanceCount":2}],
 "middlewares":[{"name":"mysql-prod-01","type":"MYSQL"}],
 "links":[{"from":"gateway","to":"order-api","count":1820,"errorCount":3,"responseTime":42.5}]}
```

**映射与流转**（DF-02）

| 源字段 | 平台结构 | 下游 |
|---|---|---|
| `nodes[]` | `.Nodes` | 排障"服务节点 N 个"；证据链原文 |
| `middlewares[]` | `.Middlewares` | 与拓扑中间件对齐 |
| `links[].errorCount/responseTime` | `.Links` | T8 按异常量/耗时取 Top N → `RISK` |
| 未知字段 | `.Raw` | 解析失败不阻断，仅降置信度 |

**有数据判据**：`len(Nodes)>0 || len(Links)>0`；否则 `NO_DATA`。

**断裂判态**

| 情形 | 判态 |
|---|---|
| `from_ts/to_ts` 传秒 | 空窗 → `NO_DATA`（Args 保留时间窗便于复核） |
| 应用名非原值 | 空/报错 → `NO_DATA` |
| 窗口内无采样 | `NO_DATA` |

## 4. Prometheus 契约

### 4.1 上游前置条件（C1–C4）

| # | 条件 | 不满足后果 |
|---|---|---|
| M-1 | `PROMETHEUS_MCP_URL` 可达 | 全部步骤 `skipped` |
| M-2 | `node_exporter` 已纳管，`instance` 为 `IP` 或 `IP:port` | `up` 无序列 → `NO_DATA` |
| M-3 | 告警规则已配置 | `list_alerts` 空 = 无活跃告警（合法） |
| M-4 | 指标名与 `host_metrics_realtime` 约定一致 | 四项全缺 → `NO_DATA` |
| M-5 | 需抑制态时 Alertmanager `/api/v2/alerts` 同源可达 | 缺 `silenced/inhibited` |
| M-6 | exemplar 采集开启（仅 K1 用） | `exemplar_query` 空 |

### 4.2 `list_alerts`（C1 I1 I2）

**请求**：`{}`（全量活跃告警）

**响应**

| 路径 | 字段 | 类型 | 默认/必读 |
|---|---|---|---|
| 数组 / `{alerts}` / `{data:{alerts}}` | `labels.alertname` | string | 必，缺失填 `(unnamed)` |
| 同上 | `labels.instance` | string | 必，主机归一唯一来源 |
| 同上 | `labels.severity \| level` | string | 缺省 `info` |
| 同上 | `annotations.summary` | string | 展示 |
| 同上 | `state` | string | `firing\|pending\|resolved` |
| 同上 | `activeAt \| startsAt` | string | RFC3339 |
| 同上 | `value` | string | 注意大写 `Value` |

**映射与流转**（DF-03 DF-12）

| 源字段 | 派生 | 平台字段 | 下游 |
|---|---|---|---|
| `labels.instance` | `NormalizeHost` | `alertView.Host` | 拓扑节点 → 影响面 |
| `alertname|instance|severity` | `lower` 拼接 | `fingerprint` | `alarm_event` upsert |
| `state` | 直取 | `.State` | 准入第 1 门 |
| 抑制态（AM） | `silenced/inhibited` | `.Suppressed` | 第 2 门 |
| `severity` | 直取 | `.Severity` | 第 3 门 |

**四道准入**：① `firing` ② 未抑制 ③ 级别达标 ④ 无进行中会话。

**断裂判态**

| 情形 | 判态 |
|---|---|
| 空数组 | `NOT_TRIGGERED`（合法） |
| 调用失败 | `error`，继续 |
| `instance` 无法归一 | 入库，影响面为空（不丢告警） |
| 大写字段无 tag | 兼容层兜底；全空 → `warn` + `NO_DATA` |

### 4.3 `query`（up 存活，C2 H1）

**请求**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | `up{instance=~"^h1(:[0-9]+)?$\|^h2(:[0-9]+)?$"}` |

**构造硬规则**：`NormalizeHost` → `regexp.QuoteMeta` → `^host(:[0-9]+)?$` → 去重 → `|` 连接；全空不发起调用。

**响应**

| 形态 | 样例 | 解析 |
|---|---|---|
| 文本行 | `{instance="10.1.2.3:9100"} => 1 @[1756143048]` | 时间戳为秒 |
| 结构 | `data.result[].metric / value[1]` | `PrometheusSamples` |

**映射与流转**（DF-04）

| 源字段 | 校验 | 平台结构 | 下游 |
|---|---|---|---|
| `metric.instance` | `aliasToHost[NormalizeHost(instance)] == Host.Key`，否则丢弃 | `map[hostKey]float64` | T7；`collectCMDB` 的 `up` 入参 |
| `value` | 1 存活 / 0 失联 | 同上 | 与 `state` 交叉判定 |

**聚合规则（J10 修正）**：同一主机多条序列 → **任一为 0 即判 0**（失联）；不得覆盖写。

**断裂判态**

| 情形 | 判态 |
|---|---|
| 无匹配序列 | `NO_DATA`（未纳管/标签不一致），不判健康 |
| 归属校验失败 | 丢弃该序列 |
| PromQL 全空 | 不调用 → `NO_DATA` |

> 反例锁：`10.1.2.3` 不得吃掉 `10.1.2.30`。

### 4.4 `host_metrics_realtime`（C3 H5）

**请求**：`{"node":"10.1.2.3"}`（也接受 `ip`）

**响应**

| 路径 | 说明 |
|---|---|
| `Payload.metrics` / `Payload.data.metrics` / 平铺 | 指标键值 |

| 字段 | 类型 | 单位 | 必读 |
|---|---|---|---|
| `cpuUsage` | float | % | 是 |
| `memUsage` | float | % | 是 |
| `diskUsage` | float | % | 是 |
| `netConnections` | int | 个 | 是 |
| 其余（cpuCores/load/netTraffic/diskIO/tcpOverflow…） | — | — | 否 |

**判定**

| 指标 | 阈值 | `P1` 升级 |
|---|---|---|
| CPU | > 85% | ≥ 95% |
| 内存 | > 85% | ≥ 95% |
| 磁盘 | > 90% | ≥ 95% |
| TCP 连接 | > 5000 | ≥ 2×（10000） |

**流转**（DF-05）：`metrics` + `thresholds` → `Finding.Evidence`；`depApps` → `Finding.Impact` → 报告/工单。

**断裂判态**：`Metrics` 空 / 四项全缺 → `NO_DATA`；部分缺失只判存在项并标注。

### 4.5 `range_query`（C4）

**请求**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 聚合后单值曲线 |
| `start_time` | string | 是 | RFC3339（也接受 Unix 秒 / `5m`） |
| `end_time` | string | 是 | RFC3339 |
| `step` | string | 否 | 如 `300s` |

**响应**：`result[].metric.__name__`、`result[].metric.instance`、`result[].values[[ts,"v"]]`（ts 为**秒**）。

**前置**：窗口内 ≥2 采样点，否则 `NO_DATA`（"采样点不足"）。

**下游**（DF-06）：劣化增长率 → degradation 告警；P50/P90 → 质差报告；单值 → 业务规则。

### 6.1 上游前置条件（E1–E3）

| E-1 | `ES_MCP_URL` 非空 | T10 恒 `NO_DATA` |

### 6.2 `list_indices`（E1）

**请求**：`{"index_pattern":"logs-*"}`
**响应**：`content[]` = `Found N indices:` + JSON 数组 `[{index,status,docs.count}]`
**解析**：`esIndexNames` 先试数组，再退回文案。
**用途**：T10 第 1 步，批次内只调一次；为空则全局 `NO_DATA`。

### 6.3 `search`（E2 H4）

**请求**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `index` | string | 是 | 与 `list_indices` 一致 |
| `query_body` | object | 是 | 固定结构见下 |

```json
{"size":0,"track_total_hits":true,
 "query":{"bool":{
   "filter":[{"range":{"@timestamp":{"gte":"now-15m"}}}],
   "must":[{"query_string":{"query":"level:(ERROR OR FATAL OR error OR fatal)","lenient":true}},
           {"query_string":{"query":"host:\"10.1.2.3\"","lenient":true}}]}}}
```

**响应与解析**

| 形态 | 解析 |
|---|---|
| `Total results: N` + 原生 `hits` | 优先正则取 N |
| `hits.total` 数字 | 直取 |
| `hits.total{value,relation}` | 取 `value`；`gte` 表示截断，标注"计数为下限" |

**判定**：`total > 20` → `RISK`；`total ≥ 100` → `P1`；否则 `NOT_TRIGGERED`。

**断裂判态**：索引不存在 → 全局 `NO_DATA`；字段不匹配 → 单机 `NO_DATA` + "字段未对齐"；无法解析 → `warn` + `NO_DATA`。

### 9.2 `up` × `state` 交叉判定

| `up` | CMDB `state` | 结论 | 指向 |
|---|---|---|---|
| 1 | 0 在线 | 健康 | — |

| 0 | 无记录 | **疑似黑户/脏数据** | 先查 CMDB 录入 |

## 10. 关键时序

### 10.1 排障（G1–G4）

```
POST /api/diagnose/sessions {appId | middlewareType+addr}
  → topo.ImpactByApp                    （本地｜影响面）
  → resolveAppIdentity                  （identity_app）
  → C1 list_alerts                      门禁：无
  → C2 query(up)                        门禁：候选主机非空
  → 【M2 验真】healthy → targets_metadata → series → E5 get_shards
                                        门禁：DIAG_VERIFY_ENABLED；失败写 sourceHealth 并降级
  → D2 cmdb_server_query                门禁：主机是 IP，≤5 台
  → B1 list_applications_tool           门禁：appId 非空；未命中 → 后续 Pinpoint 步骤 skipped
  → B2 get_server_map_tool              门禁：① 命中
  → C4 range_query                      门禁：候选主机非空；采样点 <2 判 NO_DATA
  → B4 drag_heatmap_tool                门禁：② 有数据；无 traceIds 则跳过 trace
  → B5 get_transaction_trace_tool       门禁：traceId 非空；非根 span ≥50% 判瓶颈
  → E2 search（ES，失败回退本地 log-analyzer） 门禁：候选主机非空
  → buildTicket → rank（证据集推导置信度）
  → SSE /api/diagnose/sessions/:id/stream
```

> 共 12 个上游接口调用点（Pinpoint 4 / Prometheus 6 / CMDB 1 / ES 2）。验真 4 个工具的结果写入 `sourceHealth`（`healthy`/`targets_metadata`/`series` 三条 promthus 记录 + `get_shards` 一条 es 记录），**不单独追加 `Step`**，因此会话 `steps` 通常为 10–11 条。`DIAG_VERIFY_ENABLED=false` 时写一条 `skipped` 记录，其余流程不变。

### 10.2 巡检（H1–H6）

| 证据链只有拓扑 | 网关不可用 / `MCP_ENABLED=false` | `/api/mcp/logs` 无记录 | 查开关与 URL |
| Pinpoint 两步 `skipped` | 应用名未匹配 | `Step.Result.matched=false` | 核对 `identity_app` 与原值 |
| 服务地图恒 `NO_DATA` | 时间传秒 / 窗口无采样 | `Step.Args.from_ts` 位数 | 统一毫秒；放宽窗口 |
| `up` 全无序列 | 标签非 IP / 未装 exporter | 直接在 Prometheus 查 `up` | 补采或修标签 |
| A 主机风险落到 B | 前缀误匹配 | 核对 `aliasToHost` | 严格归属校验 |
| T9 大面积 `P1` | CMDB 未覆盖 / IP 错 | 抽样 `records` | 补录/修 IP |
| T9 大面积 `NO_DATA` | `state` 缺失 | `records[0]` | 补字段，不猜默认值 |
| T10 恒 `NO_DATA` | `ES_MCP_URL` 空 / 无索引 | `/api/mcp/tools` 无 `es` | 配 URL/建索引 |
| T10 单机全 0 | `host` 字段名或值不匹配 | `get_mappings` 自检 | 修 `ES_LOG_HOST_FIELD` |
| 告警不建排障 | 四道准入未过 | 看 `Suppressed`/`state` | 逐门放行 |
| 告警重复刷屏 | fingerprint 不稳 | `instance` 是否端口漂移 | 归一后再算 |
| 报告"正常"但故障 | 空数据被当 `NOT_TRIGGERED` | 检查判态实现 | 改 `NO_DATA` |

## 14. 上游契约变更管理

| 场景 | 检测方式 | 处理 |
|---|---|---|
| 上游字段改名 | 解析成功率下降、`NO_DATA` 上升 | 先补别名（不改业务），再通知上游 |
| 上游新增字段 | 无需处理 | 需要用时走"五段式"补契约 |
| 时间单位变更 | 服务地图空窗 / 曲线错位 | 在 A4 适配层修正，不改调用方 |
| 分页上限调整 | 覆盖度下降 | 调 `IDENTITY_CMDB_PAGES` / `PAGE_SIZE` |
| ES mapping 变更 | T10 单机全 0 | E3 自检报警 + 会话内提示 |
| 工具被上游下线 | `tools/list` 缺失 | 网关启动自检记录缺失工具，功能判 `NO_DATA` |

**原则**：契约变更只允许在网关适配层吸收（A3/A4），业务模块（G/H/I）不得因上游字段变化而改动。

## 15. 报文样例（可直接作为测试 fixture）

> 样例用于断言解析路径与字段口径，**值可替换，形态不可替换**。与 §13 验收断言一一对应。

### 15.1 Pinpoint

**`list_applications_tool` — 形态 A（envelope + text 内套 JSON 字符串）**

```json
{"content":[{"type":"text","text":"[{\"applicationName\":\"order-api\",\"applicationId\":\"order-api^1780000000\",\"serviceTypeCode\":1210,\"serviceTypeName\":\"SPRING_BOOT\"}]"}],"isError":false}
```

| 断言点 | 期望 |
|---|---|
| `ResultOf` | `Payload` = 数组，长度 1 |
| `Name/ID` | `order-api` / `order-api^1780000000` |
| 缺 `applicationName` 的条目 | 丢弃，不报错 |

**`get_server_map_tool` — 形态 B（裸业务 JSON，字段走别名）**

```json
{"nodes":[{"applicationName":"order-api","serviceTypeName":"SPRING_BOOT","instanceCount":2}],
 "middlewares":[{"name":"mysql-prod-01","type":"MYSQL"}],
 "links":[{"fromApplicationName":"gateway","toApplicationName":"order-api",
           "callCount":1820,"errorCount":3,"avgResponseTime":42.5}]}
```

| 断言点 | 期望 |
|---|---|
| 节点路径 | `nodes` 命中，`Nodes` 长度 1 |
| 边别名 | `fromApplicationName/toApplicationName/callCount/avgResponseTime` 全部可解 |
| 空窗样例 | `{"nodes":[],"links":[]}` → `NO_DATA`，**不得**判 `NOT_TRIGGERED` |

### 15.2 Prometheus

**`list_alerts` — 形态 A（大写 `Value` 是已知坑）**

```json
{"alerts":[{"labels":{"alertname":"HostDown","instance":"10.1.2.3:9100","severity":"critical"},
            "annotations":{"summary":"主机不可达"},
            "state":"firing","activeAt":"2026-11-05T10:00:00Z","Value":"1"}]}
```

| 断言点 | 期望 |
|---|---|
| `labels.instance` → `Host` | `10.1.2.3`（去端口、小写） |
| `fingerprint` | `hostdown\|10.1.2.3:9100\|critical` |
| 缺 `severity` | 回落 `info`，仍入库 |

**`query`（up）— 形态 C（纯文本行，时间戳为秒）**

```
{instance="10.1.2.3:9100", job="node"} => 1 @[1756143048]
{instance="10.1.2.3:9101", job="node"} => 0 @[1756143048]
```

| 断言点 | 期望 |
|---|---|
| 聚合 | 同一主机两条序列 → **判 0（失联）**，覆盖写是缺陷 |
| 归属 | 若 `aliasToHost` 无 `10.1.2.3` 映射，两条均丢弃 → `NO_DATA` |
| 反例 | `{"instance":"10.1.2.30:9100"} => 1` 不得把 `10.1.2.3` 判活着 |

**`host_metrics_realtime` — 形态 A（`metrics` 平铺）**

```json
{"node":"10.1.2.3","metrics":{"cpuUsage":91.2,"memUsage":78.4,"diskUsage":93.1,
 "netConnections":12030,"load1":3.1,"cpuCores":8}}
```

| 断言点 | 期望 |
|---|---|
| 判定 | CPU 91.2 > 85、磁盘 93.1 > 90、连接 12030 ≥ 2×5000 → `RISK` + **`P1`** |
| `Evidence` | 含 `metrics` 与 `thresholds` 两组值 |
| 四项全缺 | `{"node":"10.1.2.3","metrics":{}}` → `NO_DATA` |

**`range_query` — 形态 A（matrix）**

```json
{"status":"success","data":{"resultType":"matrix","result":[
 {"metric":{"__name__":"node_cpu_usage","instance":"10.1.2.3:9100"},
  "values":[[1756142700,"42.1"],[1756143000,"78.6"]]}]}}
```

| 断言点 | 期望 |
|---|---|
| 时间单位 | `values[][0]` 为**秒**，平台内部转毫秒 |
| 单点 | `values` 只有 1 项 → `NO_DATA`（采样点不足） |
| 增长率 | `(78.6-42.1)/((1756143000-1756142700)/60)` = 73/分钟，用于劣化规则 |

### 15.3 CMDB

**`cmdb_server_query` — 形态 C（双层编码，必须二次 `Unmarshal`）**

```json
{"content":[{"type":"text","text":"{\"code\":200,\"message\":\"success\",\"fail\":false,\"data\":{\"records\":[{\"id\":\"cmdb-1001\",\"ip\":\"10.1.2.3\",\"hostName\":\"vm-order-01\",\"node\":\"华东-云公司-A\",\"state\":0,\"operA\":\"zhang.san\",\"operB\":\"li.si\",\"environment\":\"prod\",\"specification\":\"8C16G\"}],\"total\":1,\"currentPage\":1,\"pageSize\":5,\"pages\":1}}"}]}
```

| 断言点 | 期望 |
|---|---|
| 二次解码 | `ResultOf.Payload` 再解 → `data.records` |
| `state=0` | `Online=true`，与 `up=1` 组成健康象限 |
| `state=4/6` 且被应用引用 | 判 `P1`（报废/清退仍在承载） |
| 无 `state` 字段 | `NO_DATA`，**不猜默认在线** |
| 空记录 | `records:[]` → `P1` 账实不符 |

### 15.4 Elasticsearch

**`list_indices` — 形态 C（文案 + JSON 混排）**

```json
{"content":[{"type":"text","text":"Found 2 indices:\n[{\"index\":\"logs-app-2026.11.05\",\"status\":\"open\",\"docs.count\":\"128340\"},{\"index\":\"logs-gateway-2026.11.05\",\"status\":\"open\",\"docs.count\":\"99210\"}]"}]}
```

**`search` — 形态 C（统计文案 + 原生 hits）**

```json
{"content":[{"type":"text","text":"Total results: 37\n{\"hits\":{\"total\":{\"value\":37,\"relation\":\"eq\"},\"hits\":[]}}"}]}
```

| 断言点 | 期望 |
|---|---|
| 计数 | 优先正则 `Total results: (\d+)` → 37 |
| `relation=gte` | 样例改为 `{"value":10000,"relation":"gte"}` → 报告标注"计数为下限" |
| 阈值 | 37 > 20 → `RISK`；≥100 → `P1` |
| `total=0` | 有效值，判 `NOT_TRIGGERED`，不是 `NO_DATA` |

### 15.5 平台落盘样例

**`domain.Step`（排障证据链 · Pinpoint 命中）**

```json
{"source":"pinpoint","tool":"get_server_map_tool","title":"Pinpoint 服务地图",
 "status":"ok","args":{"application_name":"order-api","from_ts":1762317600000,"to_ts":1762318500000},
 "result":{"bytes":412,"nodes":2,"middlewares":1,"links":3,"truncated":false},
 "latencyMs":183,"at":"2026-11-05T10:15:00+08:00"}
```

**`domain.Finding`（巡检 T11 · 风险）**

```json
{"ruleCode":"TOPO_T11","title":"主机指标阈值","verdict":"RISK","severity":"P1",
 "objectType":"host","objectKey":"10.1.2.3",
 "detail":"3 项指标超阈值：CPU 91.2% > 85%；磁盘 93.1% > 90%；TCP 连接数 12030个 > 5000个；被 2 个应用依赖",
 "evidence":{"host":"10.1.2.3","metrics":{"cpuUsage":91.2,"diskUsage":93.1,"netConnections":12030},
             "thresholds":{"cpuThreshold":85,"diskThreshold":90,"connThreshold":5000}},
 "impact":{"host":"10.1.2.3","depApps":2}}
```

**`alarm_event`（告警入库 · 幂等键）**

```json
{"fingerprint":"hostdown|10.1.2.3:9100|critical","alertName":"HostDown",
 "instance":"10.1.2.3:9100","host":"10.1.2.3","severity":"critical","state":"firing",
 "suppressed":"","activeAt":"2026-11-05T10:00:00Z","source":"prometheus",
 "labels":{"alertname":"HostDown","instance":"10.1.2.3:9100","severity":"critical"}}
```

| 断言点 | 期望 |
|---|---|
| 重复推送 | 同 `fingerprint` 二次推送 → 事件数仍为 1，仅更新 `state` |
| 端口漂移 | `:9100` 与 `:9101` 是两条事件（`fingerprint` 用 `instance` 原值），需在告警侧收敛 |
| 抑制 | `suppressed=silenced` → 准入门第 2 道拦截，不建排障 |
