## 一、修订缘起

来自《api/tprel 梳理与测试报告》中指出的两点口径偏差（非缺陷，但需对齐）：

1. **file 模式 `/list` 的 `id` 恒为 `0`**（无 DB 自增主键），「分页按 id 倒序」在 file 模式不可观测；且 `pageTotal` 实测默认展开远大于文档示例的 1418（折叠口径）——当轮为 10192，2026-09-20 快照为 **5266**。
2. **`/graph` 示例 `counts.nodes=449`** 属折叠口径，但 §3.1 又写明 `expandDepNode` 默认展开，示例相对默认口径偏旧。

处理方式：不改代码，仅将「仅在折叠口径成立」的表述补齐口径限定，并统一互引《运维拓扑.md》§4.5 作为权威出处。

## 二、核心口径对照

权威出处：`运维拓扑.md` §4.5（**2026-09-20 快照、`env=PRO` 实测**；量级随每日快照变化）。

| 指标 | 折叠（显式 `expandDepNode=0`） | 默认展开（不传 / `1` / `true`） |
| --- | --- | --- |
| 应用节点粒度 | `app:{appId}` | `app:{appId}\|{部署项目}\|{节点}` |
| 应用节点数 | 108 | **240** |
| 中间件节点数 | 341 | 341 |
| 依赖边数 | 756 | **2943** |
| graph `nodes` | 449 | **581** |
| `/list` `pageTotal` | 1418 | **5266** |

关键语义：

- `expandDepNode` 为 `*bool` 三态：`nil`（不传）/ `true` / `1` → 展开（默认）；显式 `false` / `0` → 折叠。
- 展开**只在查询期、不落库**：唯一索引 `uk_snapshot_relation(sync_date, apollo_app_id, apollo_host_id, env, middleware_type, connect_addr)` 不含 `dep_project` / `node`。
- 应用 id 随口径变化，**跨口径不可复用**（节点/连线 key、详情入参、本地选中态均需同口径）。
