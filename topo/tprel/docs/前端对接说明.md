## 1. 访问方式与鉴权

### 1.1 两种访问环境

| 环境 | 请求地址 | 鉴权 | 说明 |
|---|---|---|---|
| 主项目（正式/联调） | `{BASE}/api/external/operationTopology/*` | 需 JWT（见 1.2） | 路由挂在 `/api/external` 组，经 `JWTAuth` 中间件 |
| 本地独立测试服务 | `http://127.0.0.1:8098/api/external/operationTopology/*` | **无需鉴权** | `go run ./api/tprel/test/server` 启动，仅供原型/联调（需先 `docker compose up -d` 起 mock apollo） |

- **`{BASE}` 取部署方给出的地址**（`http://{服务器IP或网关}:{端口}`，端口以 `system.addr` / 网关转发为准）。下文 curl 示例中的 `http://127.0.0.1:8867` 只是**本机主程序默认地址**（[config_test.yaml L98](../../../config_test.yaml#L98)），**正式对接请整体替换为 `{BASE}`**。
- 正式对接前，向部署方索取：① `{BASE}`；② 一个有效 JWT（由现网登录接口签发）；③ 期望的环境参数 `env`（当前部署采集 **PRO** 环境；以部署方告知为准；不传=不按环境过滤）。
- **本地测试服务附带的前端原型**（可用来对照接口效果）：
  - 本机：`http://127.0.0.1:8098/prototype/topology_g6.html`
  - 同局域网其它电脑：`http://<本机局域网IP>:8098/prototype/topology_g6.html`（服务监听 `0.0.0.0:8098`，见 [main.go L105](../test/server/main.go#L105)）
  - 附带本地专用接口：`GET /healthz`（健康检查）、`GET /api/external/operationTopology/doc`（在线查看/下载本文档，`?download=1` 为 markdown 附件；**仅本地服务注册，生产不提供**）

### 1.2 JWT 鉴权约定（仅主项目环境）

- 请求头字段名：**`token`**（注意：不是 `Authorization`，也不带 `Bearer ` 前缀），值 = 登录后返回的 JWT 原文：

  ```
  token: eyJhbGciOiJIUzI1NiIs...
  ```

  > 后端 [middleware/jwt.go L20](../../../middleware/jwt.go#L20) 固定读取 `token` 请求头。

- token 缺失/失效/过期 → **HTTP 状态码仍为 200**，鉴权失败体现在响应体 `code`：

  ```json
  { "code": 401, "data": { "reload": true }, "msg": "未登录或非法访问 / 授权已过期" }
  ```

  > ⚠️ **切勿按 HTTP 状态码判断**：后端统一 `c.JSON(http.StatusOK, ...)`（[response.go L46-53](../../../model/response/response.go#L46-L53)），鉴权失败/业务失败也返回 **HTTP 200**，须判断 `body.code`。

- 前端收到 `data.reload = true` 应跳转登录；token 临近过期（剩余 < 缓冲时间）时，中间件会自动签发新 token 并通过响应头带回：`new-token` / `new-expires-at`，前端应取出**覆盖本地存储**并用于后续请求。
- **特别提醒（sessionId cookie）**：中间件还会校验 `sessionId` cookie——若浏览器请求**自动携带了同名 cookie**，其值必须与 token 中用户角色一致，否则同样返回 `code:401`（见 [jwt.go L21-56](../../../middleware/jwt.go#L21-L56)）。因此页面 fetch 时应避免把无关的 `sessionId` cookie 一起带上（跨域/网关场景通常无此 cookie，可忽略）。
- 本地测试服务（8098）不走 JWT，无此约定。

### 1.3 通用要求

- 所有接口返回 `Content-Type: application/json`，编码 UTF-8
- 请求/响应字段均使用 **camelCase**
- GET 参数放 **Query**；POST 无需请求体
- 所有参数均为**可选**，不传则走服务端默认值
- ~~`X-Data-Source` 响应头已下线~~：各接口不再返回该响应头。数据源仅由 **`GET /graph` 返回体** 的 `data.dataSource` 字段携带（`db`=读数据库（默认），`file`=回退本地镜像文件），用于展示"数据来源"徽标
- Query 参数含中文/特殊字符时需 **URL 编码**（前端用 `encodeURIComponent`，例如 `apolloHostName=广州4多AZ` 需编码为 `%E5%B9%BF%E5%B7%9E4%E5%A4%9AAZ`）；连接地址 `host:port` 中的 `:` 无需编码
- 联调自验可用文档内各接口小节末尾的 **curl 示例**（服务器本机或带网关地址均可）

## 2. 接口总览

| # | 方法 | 路径（前缀 `/api/external/operationTopology`） | 用途 | 前端场景 |
|---|---|---|---|---|
| 1 | GET | `/graph` | 拓扑图 nodes + edges（一次全量） | **主视图渲染** |
| 2 | GET | `/detail` | 单个节点详情（含关联明细） | 点击节点后**详情面板** |
| 3 | GET | `/list` | 关系明细分页查询 | 表格/明细溯源/调试 |
| 4 | POST | `/sync` | **异步提交**一次全量采集（立即返回，结果轮询 `/sync/status`） | 「手动同步」入口 → 弹窗内「开始同步」 |
| 5 | GET | `/sync/status` | 同步任务状态/结果（提交后轮询） | 同步进度/结果展示 |
| 6 | GET | `/sync/logs` | 最近同步日志读取/下载（同步后排障） | 「下载同步日志」/日志查看入口 |
| 7 | GET | `/middlewareTypes` | 中间件类型枚举 | 筛选下拉数据源 |

> 章节对应：§3 `/graph`、§4 `/detail`、§5 `/list`、§6 `/sync` + `/sync/status` + `/sync/logs`（接口四~六，同一弹窗交互）、§7 `/middlewareTypes`。所有路径的完整形式为 `{BASE}/api/external/operationTopology/{接口}`；下文 curl 中出现的 `http://127.0.0.1:8867` 为**本机主程序默认地址**占位，正式对接替换为 `{BASE}`（见 §1.1）。

### 2.1 两种响应信封（重要）

| 信封 | 接口 | 结构 |
|---|---|---|
| 标准信封 | graph / detail / sync / sync/status / sync/logs / middlewareTypes | `{ "code": 0, "data": {...}, "msg": "操作成功" }` |
| 列表信封 | list | `{ "code": 0, "list": [...], "pageTotal": 1418 }`（**无 msg/data 字段**） |

> `list` 的 `code` 已统一为**数字 0**，与其余接口一致，前端按 `code === 0` 判断成功即可。
> 例外：`/sync/logs` 请求带 `download=1` 时**不返回 JSON**，直接以附件下载完整日志文件（浏览器触发保存），此时无需按信封解析。
> 上表 `pageTotal` 示例为**折叠口径**（`expandDepNode=0`，= 快照关系行数 1418）；**默认展开**时为 **5266**（按部署点扩行后的行数，随每日快照变化）。口径差异详见 §5.2 与《[运维拓扑.md](运维拓扑.md)》§4.5。

### 2.2 失败/异常

```json
{ "code": 7, "data": {}, "msg": "查询失败: <原因>" }
```

- 业务错误统一 `code = 7`；鉴权错误 `code = 401`（**HTTP 状态码同为 200**，见 §1.2）
- 前端只需判断：`code === 0` 即成功（两种信封一致）

### 2.3 页面加载建议

- 首次进入：先拉 `GET /middlewareTypes` 填筛选下拉（可选）；再拉 `GET /graph` 渲染主视图
- 主视图数据只来自 `/graph`；`nodes` 为空时展示空态并提供「手动同步」入口（仅打开同步面板，弹窗内点击「开始同步」才 `POST /sync` + 轮询 `GET /sync/status`，见 §6）
- 点击节点 → 用该节点 `id` 请求 `GET /detail`（无需重拉 graph）
- 所有请求统一带 `token`；筛选（env / middlewareType）变化时重新请求 `/graph`

## 3. 接口一：拓扑图 `GET /graph`

> 前端主数据接口。返回可直接渲染的图结构，聚合逻辑在后端完成（应用按 appid 合并、中间件按 类型+地址 合并、实例层单独给出）。

### 3.1 请求参数（Query，全可选）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `env` | string | 无（不限） | 环境过滤，如 `PRO` |
| `middlewareType` | string | 无（不限） | 中间件类型过滤，如 `mysql` |
| **`depProject`** | string | 无（不限） | **appId 属性**：部署项目名（**模糊**）；过滤粒度是 appId，命中即保留该 appId 的全部节点与关系边 |
| **`engProject`** | string | 无（不限） | **appId 属性**：工程项目名（**精确**）；同上，命中即保留该 appId 全部关系 |
| **`node`** | string | 无（不限） | **appId 属性**：机房/节点，如 `ct-yk`（**精确**）；同上。**⚠️ 见下方「`node` 属性可用性」注** |
| **`ppApplication`** | string | 无（不限） | **appId 属性**：PP 应用名（**精确**）；同上 |
| `syncDate` | string | 最新快照 | 历史快照日期 `YYYY-MM-DD`（对比回看用，不建议默认传） |
| `source` | string | 无（默认 `db` 优先，不可用回退 `file`） | 数据源覆盖 `db\|file`（一般无需传；与 `/detail`、`/list` 同名参数一致） |
| **`expandDepNode`** | bool | **`true`（默认展开）** | **部署点展开开关**：应用节点粒度取 `appId + 部署项目 + 节点`（一个部署点一个节点，属性为单值）；显式传 `0`/`false` 折叠为 `appId` 一个节点，属性多值聚合为列表（`depProjects` 等） |

> 多个过滤参数叠加（AND 关系）；`env` 建议总传（不传则多环境数据合并聚合）；`middlewareType` 可选值来自 `GET /middlewareTypes`（随数据自动扩展）。
> **appId 属性四参数（`depProject` / `engProject` / `node` / `ppApplication`）与 `/list` 同口径**：属性属 appId 级（查询期两跳关联补充，无关系数据时为空），任一条件命中即保留该 appId 的全部中间件关系（不因属性值多而拆节点/拆边）；**同一参数可传逗号分隔多值，多值之间为 OR（任一命中即算该维度命中），不同参数之间为 AND**。前端「属性筛选」为四维可多选 chips（`depProject` 模糊匹配、其余精确匹配），与本表一一对应。
> **`expandDepNode` 建议总传**：后端「不传（缺省）」等价于**展开**，前端若要折叠必须显式传 `0`；`/graph`、`/list`、`/detail` 三入口同口径，详情应与图/列表**同值**传入（否则详情与图节点粒度不一致）。两种口径的实测规模（应用节点 240 vs 108、边 2943 vs 756，2026-09-20 快照）与筛选粒度差异见《[运维拓扑.md](运维拓扑.md)》§4.5。
> **⚠️ `node` 属性可用性（数据侧问题，非接口缺陷）**：`node` / `engProject` 由查询期两跳关联（`app_dp_relation` → `deploy_pinpoint_relation`）回填，**当前快照回填率极低**——快照部署项目与 DPR 的 108 个部署项目几乎无交集，导致绝大多数应用节点的 `node` 为空串，按 `node` 过滤通常返回**空图**（`counts` 五项全 0）。**前端在数据修复前不要把「机房」作为必选/默认筛选项**；需要展示机房时先判断节点 `node` 是否非空，否则显示「未知」。

| category | id 格式 | 示例 |
|---|---|---|
| `application`（应用层，**默认展开**） | `app:{apollo_app_id}\|{部署项目}\|{节点}` | `app:cloud-ehome\|cloud-ehome-prod-114804-dep\|`（示例取自 2026-09-20 快照，建议以 `/graph` 实际返回为准） |
| `application`（应用层，**折叠** `expandDepNode=0`） | `app:{apollo_app_id}` | `app:apollo-ehome-pro` |
| `middleware`（中间件层） | `mw:{middleware_type}:{addr}` | `mw:mysql:ehome-pro.mysql.ehomeinner.cn:13302` |
| `host`（实例层，非 graph nodes 内） | `host:{apollo_host_id}` | `host:13` |

> **id 随口径变化（前端必须注意）**：应用节点 id **取决于 `expandDepNode`**——默认展开时为 `app:{appId}|{部署项目}|{节点}`（一个部署点一个节点），折叠时为 `app:{appId}`。这直接影响三件事：①**节点/连线 key 不可跨口径复用**（后端会按「当前 `expandDepNode`」重新生成 id，图中 `id` 与 `edges.source` 始终同口径，前端只消费不拼接）；②**存/取详情入参要同口径**：展开态的应用 id 自带 2 个 `|`，后端一律按部署点定位（即使详情入参写 `expandDepNode=0` 也如此，见《[运维拓扑.md](运维拓扑.md)》§4.5「详情 id 自适应」）；而 `mw:` / `host:` id 不含部署点信息，其「引用应用列表」粒度只能由入参决定，**前端请求 `/detail` 时应与 `/graph` 传同值**；③**本地状态（选中/高亮/固定节点）在切换口径后需按新 id 重建**，不能用折叠态 id 去匹配展开态图。

**节点（graph 的 nodes 只含 application + middleware 两类）**

| 字段 | 节点类型 | 用途/渲染建议 |
|---|---|---|
| `id` | 全部 | 节点唯一标识（连线 source/target 用它；点击后传给 `/detail`） |
| `category` | 全部 | `application` / `middleware`，决定分组与样式 |
| `name` / `label` | 全部 | 主标题 / 副标题（应用：name=应用名，label=appid；中间件：name=label=`类型:地址`） |
| `apolloAppId` / `apolloAppName` | 应用 | appid / 应用名 |
| `appDept` / `appOwner` | 应用 | 部门 / 负责人（tooltip/详情） |
| `node` / `engProject` / `depProject` | 应用 | 机房/工程/部署项目（**查询期两跳关联作为 appId 属性补充**，单值列取属性列表首值，多值见 `nodes` / `engProjects` / `depProjects` 列表字段，无关系数据时为空） |
| `nodes` / `engProjects` / `depProjects` / `ppApps` | 应用 | 该 appId 的**多值属性列表**（去重升序）：机房 / 工程 / 部署项目 / PP 应用；同一 appId 多行属性取**并集**，不分裂节点（**折叠口径** `expandDepNode=0`；**默认展开**时应用节点即部署点粒度、四个多值列表清空，见上方「id 规范」注与《[运维拓扑.md](运维拓扑.md)》§4.5） |
| `ppApp` | 应用 | PP 应用名 |
| `apolloHosts` | 应用 | **Apollo 实例（套）归属列表** `[{id, name, host, appCount}]`——同一应用跨多套实例时含多条。前端据此渲染「实例层节点 + host→app 归属边」，并可做实例维度筛选/搜索 |
| `mwType` / `addr` / `mwProject` | 中间件 | 中间件类型 / host:port / 项目名 |
| `appIds` | 中间件 | 依赖该中间件的**应用节点 id 清单**（悬停高亮/详情用） |
| `depCount` | 中间件 | 被依赖应用数 → 角标（扇入热度） |

> **appId 属性筛选（前端本地）**：应用节点的多值属性 `depProjects` / `engProjects` / `nodes` / `ppApps` 即前端「属性筛选」的匹配对象（多值列表优先，单值字段 `depProject`/`engProject`/`node`/`ppApp` 回退）。匹配口径与后端 `/graph` 的 `depProject`(模糊) / `engProject`(精确) / `node`(精确) / `ppApplication`(精确) 四参数**完全一致**：**同一维度可多选，多值之间 OR；维度之间 AND**；命中即保留该应用的全部依赖；中间件节点按「其来源应用中是否有命中者」保留，实例层按「其名下应用是否有命中者」保留；命中应用不受前端密度裁剪，保证筛选结果完整。前端本地筛选为即时交互、无需回传后端；如需服务端裁剪，则请求 `/graph` 时直接带上述四参数（同一参数可传逗号分隔多值，两者可叠加使用）。

**顶层 `data.apolloHosts`**：本次图内出现的实例（套）汇总（`[{id, name}]`，按 id 排序）。可作为「实例筛选下拉」数据源，也可供搜索候选"实例名"匹配。

**顶层 `data.counts`**（规模汇总，供统计卡/角标等展示用）：与**当前过滤条件一致**的列表规模——`apolloHosts`=返回 `data.apolloHosts` 数组长度；`application`/`middleware`=返回 `nodes` 中对应 `category` 的节点数量；`edges`=返回 `edges` 条数；`nodes`=节点总数（`=application+middleware`）。空图（无数据）时五项全为 0。**仅 `/graph` 返回该字段**，`/list`、`/detail`、`/middlewareTypes`、`/sync`、`/sync/status` 均无。

**边（edges）**：`source`（应用 id）→ `target`（中间件 id），`kind` 恒为 `depend`；同一条后端已去重，无需前端再判。

> **实例（host）层渲染建议**：graph 只给"应用 → 中间件"边与应用的 `apolloHosts` 归属。若页面需要实例层节点，用顶层 `apolloHosts` 建 host 节点，并按应用节点的 `apolloHosts` 归属生成「实例 → 应用」虚线边（前端本地处理，无需后端参数）。

### 3.4 空数据/未同步

当日无快照或过滤后无匹配时，HTTP 仍 200，`data.nodes` 为空数组：

```json
{ "code": 0, "data": { "nodes": [], "edges": [], "apolloHosts": [], "syncDate": "", "env": "", "partial": false, "dataSource": "file", "counts": { "apolloHosts": 0, "application": 0, "middleware": 0, "edges": 0, "nodes": 0 } }, "msg": "暂无数据（今日未同步或无匹配）" }
```

## 4. 接口二：节点详情 `GET /detail`

> 点击图节点后拉取右侧详情面板：后端按节点类别聚合出该节点的归属/关联明细（应用依赖了哪些中间件、中间件被哪些应用依赖、实例名下有哪些应用），并附被依赖数等统计，前端只负责渲染。

### 4.1 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 图节点 id（`app:{appid}\|{部署项目}\|{节点}` / `app:{appid}` / `mw:{type}:{addr}` / `host:{host_id}`），**须与 `/graph` 同口径** |
| `env` | string | 否 | 环境，默认最新快照；**不传时不按环境过滤，且响应中的 `env` 字段为空字符串**（后端按入参原样回填，不做推断），前端需展示环境标识时请**显式传入** |
| `syncDate` | string | 否 | 快照日期，默认最新 |
| `expandDepNode` | bool | **`true`（默认展开）** | 与 `/graph` **同值传入**：展开态下 `mw:` / `host:` 节点的「引用应用列表」为部署点粒度，折叠则为 appId 粒度；**应用节点 id 自带 2 个 `|` 时后端一律按部署点定位**（此时该参数对结果无影响）。见《[运维拓扑.md](运维拓扑.md)》§4.5 |

## 5. 接口三：关系列表 `GET /list`

> 明细视图/调试溯源用：一行 = 一条「应用 → 中间件」关系，可追溯到具体 namespace / config key。

### 5.1 请求参数（Query，全可选）

| 参数 | 类型 | 默认 | 匹配方式 / 说明 |
|---|---|---|---|
| `page` | int | 1 | 页码（从 1 开始） |
| `pageSize` | int | 20 | 每页条数；**传负数（如 -1）表示不分页、一次返回全部**（联调/导出用）；省略或 0 按 20 |
| `env` | string | - | **精确**（环境，如 `PRO`） |
| `middlewareType` | string | - | **精确**（类型，来自 `/middlewareTypes`） |
| `apolloAppId` | string | - | **精确**（appid，如 `apollo-ehome-pro`） |
| `apolloHostName` | string | - | **模糊**（实例/套名称，如 `广州` 或名称片段） |
| `connectAddr` | string | - | **模糊**（host:port 片段，如 `ehome-pro.mysql`） |
| `apolloAppName` | string | - | **模糊**（应用名称） |
| `appDept` | string | - | **模糊**（所属部门） |
| `appOwner` | string | - | **模糊**（负责人） |
| `depProject` | string | - | **模糊**（部署项目；查询期两跳关联作为 appId 属性补充，无关系数据时为空；过滤粒度是 appId，命中即保留该 appId 的全部关系行） |
| `engProject` | string | - | **精确**（工程项目；查询期两跳关联作为 appId 属性补充，无关系数据时为空；过滤粒度是 appId，命中即保留该 appId 的全部关系行） |
| `node` | string | - | **精确**（机房；查询期两跳关联作为 appId 属性补充，无关系数据时为空；过滤粒度是 appId，命中即保留该 appId 的全部关系行） |
| `ppApplication` | string | - | **精确**（PP 应用名；查询期两跳关联作为 appId 属性补充，无关系数据时为空；过滤粒度是 appId，命中即保留该 appId 的全部关系行） |
| `syncDate` | string | 最新快照 | 精确 `YYYY-MM-DD` |
| `expandDepNode` | bool | **`true`（默认展开）** | 部署点展开开关（与 `/graph`、`/detail` 同口径）：不传即展开（按部署点扩行）；显式 `0` 折叠为 appId 粒度（属性补充不扩行）。**影响 `pageTotal`（展开 5266 / 折叠 1418，2026-09-20 快照）**，见 §5.3 与《[运维拓扑.md](运维拓扑.md)》§4.5 |
| `source` | string | 无（默认 `db` 优先，不可用回退 `file`） | 数据源覆盖 `db\|file`（一般无需传） |

> 搜索建议用 `apolloAppId` / `apolloHostName` / `connectAddr` / `apolloAppName`（模糊命中）；筛选用 `env` / `middlewareType`。
> **返回排序**：分页时按 `id` **倒序**（等价 DB 端 `ORDER BY id DESC`；file 快照按行序倒序输出，两种数据源顺序一致），即行号大的在前；`pageSize` 传负值（不分页取全量）时按 `id` 升序输出，供聚合/导出使用。
> **`id` 与排序的观测差异**：`id` 是 DB 表自增主键，**file 模式下恒为 `0`**（见《[运维关系拓扑图方案.md](运维关系拓扑图方案.md)》§3.3）。此时「倒序 / 升序」只体现为**行序**，前端不能用 `id` 判读顺序、也不要自行重排；只有 DB 模式下 `id` 才是有值且可比较的。

> `pageTotal` 是**候选关系行数**（示例为折叠口径 = 快照关系行数 1418）；**默认展开**时该值为 **5266**（按部署点扩行后的行数，随每日快照变化），展开态下 `depProject` / `node` 为单值、多值列表清空。两种口径的实测对照见《[运维拓扑.md](运维拓扑.md)》§4.5。
> `depProject` / `engProject` / `node` / `ppApplication` 四列由查询期两跳关联作为**该 appId 的属性补充**（单值列取属性列表首值，多值走 `depProjects` / `engProjects` / `nodes` / `ppApplications` 列表），**折叠口径下不扩行**、行数与行序不变；默认展开口径下行为部署点粒度（见上条）。

### 5.3 字段说明

| 字段 | 说明 |
|---|---|
| `apolloHostId` / `apolloHostName` / `apolloHostAddr` / `appCount` | 该条关系所属 **Apollo 实例（套）** 信息（顶层归属维度；同一应用跨多套实例时按实例各存多行） |

## 6. 接口四~六：手动同步 `POST /sync`（异步）＋ 状态轮询 `GET /sync/status` ＋ 日志 `GET /sync/logs`

> 「手动同步」打开弹窗 → 点击弹窗内「开始同步」触发：从 Apollo 全量采集一次并覆盖写入当日快照。
> **同步为分钟级长任务**，走 HTTP 网关/负载均衡会超时（504），故 `/sync` 改为**异步提交**（立即返回），结果通过轮询 `/sync/status` 获取。

### 6.1 前端交互流程（重要）

1. **外层入口不触发同步**：页面上的「手动同步」按钮仅是**入口**，点击后打开同步弹窗并**先查询一次** `GET /sync/status`（此刻**不调用** `POST /sync`），按状态渲染：
   - `data.running=true`（有任务在执行/排队——可能来自其它页面或 01:30 定时任务）→ 直接展示**进度面板**并恢复轮询（见步骤 3），**不提供**「开始同步」按钮；
   - `data.running=false` 且 `data.error` 非空 → 展示上次失败原因 + 「重试同步」；
   - `data.running=false` 且 `data.result` 存在 → 展示「最近一次同步 · 整体效果」；
   - 空闲且无任何记录 → 展示**起始面板**（说明 + 「开始同步」按钮）。
2. **弹窗内点击「开始同步」才真正提交**：`POST /sync`（无请求体；生产带 `token`）：
   - `data.started=true`：任务已提交，进入轮询；
   - `data.started=false`（已有任务在执行/排队）：同样进入轮询，无需重复提交。
3. 轮询 `GET /sync/status`（原型实现为 1 秒以获得平滑进度条；**生产建议 3~5 秒**——该接口与其它 `/api/external` 接口一样，每次请求都会写一行 `sys_operation_record` 操作日志，秒级高频轮询会增加服务端日志表写入），**同一弹窗**内实时更新：
   - `data.running=true`：弹窗标题「正在同步 Apollo 配置…」，展示 **进度条 + 规模统计卡**——
     - 进度条：按 `data.percent`（0~100）定量填充；`data.percent=-1` 时该阶段无定量进度（如探活/拉应用列表），改用**不确定滑动动画**；下方小字为 `data.stageText`（如「正在扫描配置 456/1077」）+ `data.costMs` 已耗时；
     - 统计卡：Apollo 套 `stats.hosts`、应用 `stats.apps`（组装后即确定）、中间件 `stats.middleware`、连接关系 `stats.relations`（后两者随扫描实时增长）；`stats` 为空时显示「—」；
     - 运行期间**不提供「开始同步」按钮**——全局仅一个同步任务（与 01:30 定时任务共用服务端互斥锁），重复触发不生效；
   - `data.running=false` 且 `data.error=""`：**任务结束**，同一弹窗切换为「本次同步 · 整体效果」，顶部保留最终统计卡，下方用 `data.result` 展示明细与类型分布，并提供「再次同步」；若 `data.result.partial=true` 且本地已有可用旧快照 → 本次**未覆盖**：页面保持旧版数据并提示「已保留现有快照 N 条，本次未覆盖」；仅从未同步过（无可用旧快照）时才先落部分数据并提示「本次为部分结果」；
   - `data.error` 非空：**失败**，弹窗提示 `data.error`，确认空闲后可「重试同步」。
4. **弹窗可随时关闭**（右上角 × / 点击遮罩）：只停止本页轮询，**后台任务不中断**；再次打开「手动同步」会**先查询状态**——仍在执行/排队则自动恢复进度并继续轮询，已结束则展示最新结果/失败/起始面板。
5. 低频触发（仅「今日无数据/数据异常」时让用户点）。

> 说明：`newRelations`/`lostRelations` 是**与上一次成功同步的差集**，首次或上一次快照缺失时为 `null`、`newCount` = 全部行数、`lostCount` = 0（本例即如此）。

**状态层字段说明（进度条 / 统计卡渲染用）：**

| 字段 | 含义 | 前端渲染 |
|---|---|---|
| `stageText` | 当前阶段文案（如「正在扫描配置 456/1077」），随阶段自动变化 | 进度条下方小字展示 |
| `percent` | 完成度 **0~100**；`-1` = 当前阶段无定量进度（探活/拉应用列表阶段） | `>=0` 走**定量进度条**；`-1` 走**不确定滑动动画** |
| `costMs` | 任务已耗时（running 中）或总耗时（完成后） | 可展示「已耗时 xx 秒」 |
| `stats.hosts` | 扫描的 Apollo 套总数 | 统计卡「Apollo 套」 |
| `stats.apps` | 应用总数（任务组装后即确定） | 统计卡「应用」 |
| `stats.middleware` | 已识别中间件节点数（类型+地址 去重，随扫描实时增长） | 统计卡「中间件」 |
| `stats.relations` | 已解析连接关系条数（随扫描实时增长） | 统计卡「连接关系」 |
| `result` | 完成后才非空：本次完整同步结果 | 完成后展示结果摘要（见 6.4） |

> `stats` 字段在任务组装前为空（`null`），此时统计卡显示「—」。阶段推进顺序：`任务已提交，等待执行` → `正在探测 Apollo 套可用性`(-1) → `正在拉取应用列表`(-1) → `扫描任务就绪，共 N 项` → `正在扫描配置 d/N`(0~100) → `正在对比并生成快照`(100)。

### 6.4 result 字段含义（前端提示用）

| 字段 | 说明 | 前端建议 |
|---|---|---|
| `hostCount` / `availableHosts` | 扫描套数 / 可用套数 | 若 `availableHosts << hostCount` 提示「部分 Apollo 套不可用」 |
| `appCount` / `requestCount` / `insertCount` | 应用数 / 请求数 / 落盘关系数 | 结果摘要 |
| `triggerBy` / `startTime` / `endTime` / `costMs` | 触发方式（`手动同步(页面/sync接口)` / `cron定时` / `启动自检` / `e2e自检`）/ 开始 / 结束 / 总耗时 ms | 「本次同步 · 整体效果」头部摘要 |
| `resultText` | 结果描述（`成功` / `部分完成(未执行任务/未完成应用)`；跳① 异常时追加 `（关系同步异常）`） | 结果面板标题文案 |
| `relationRows` / `relationWrote` | 跳① 关系同步本次拉取行数 / 是否执行了替换落库（数据无变化跳过替换时为 `false`，属正常） | 「跳① 关系同步」摘要（可选展示） |
| `relationErr` / `relationMsg` | 跳① 是否**异常**（`true` 需运维介入）/ 结果说明 | `relationErr=true` 时提示「关系同步异常」并展示 `relationMsg`；**接口未启用 / 0 行 / 无数据库连接属正常降级**（`false`），不提示异常 |
| `avgRequestMs` / `maxRequestMs` | 单请求平均 / 最大耗时 ms | 性能摘要（可选展示） |
| `totalRelations` | 本次解析去重后的总关系数 | 结果摘要（与 `insertCount` 同口径） |
| `keptRows` | 本次无解析产物时**保留的当日旧快照行数**（>0 = 本次未覆盖） | 提示「已保留当日旧快照 N 条，本次未覆盖」 |
| `partial` | 是否预算超时**部分完成** | `true` 且已有可用旧快照 → **不覆盖**、保留旧快照（页面保持旧版数据，提示「已保留现有快照，本次未覆盖」）；仅无旧快照时才落部分数据并提示「本次为部分结果」 |
| `unfinishedApps` | 未完成抓取的应用列表 | 排查 Apollo 侧故障 |
| `newRelations`/`newCount` / `lostRelations`/`lostCount` | 与上次快照相比 新增/消失 的关系 | 变更摘要（关系数组可能较大，建议只展示数量）；`newRelations` 元素格式 `appid\|实例名\|env\|类型\|地址` |
| `prevDate` | 对比的上次快照日期 | 变更基于哪个日期对比 |
| `nodeStats` | `map[类型]节点数`：中间件**节点**分布，按「类型 + 连接地址」去重（与 `/graph` 图节点口径一致） | 结果弹窗类型分布图（节点维度） |
| `typeStats` | `map[类型]关系数`：中间件类型**关系**分布（**含实例重复**，同一类型多条关系均计入） | 结果弹窗类型分布图（关系维度） |
| `noMiddlewareCount` / `noMiddlewareApps` | **无中间件应用**数（int）与清单（`[{appId, appName}]`，按 `appId` 升序）。口径：本次「已实际执行过 namespace 拉取（任意 ns 有返回即算，404 也算）」但「未解析出任何中间件关系行」的应用；**排除**未完成（拉取失败）与未执行（预算截断未轮到）应用——没扫到的不算「无中间件」 | 同步结果弹窗/详情可展示「无中间件应用 N 个」，并可展开 appId+名称，便于核对是否漏配中间件 |
| `nsTargeted` / `nsBootstrap` / `nsRecheck` | namespace 扫描策略计数：定向（命中学习集）/ 全名单首扫（建立基线）/ 兜底重猜（超期全量），单位为 `hostId\|env\|appId` 三元组 | 后端排障指标，前端可不展示 |

> §6.3 的「完成后」示例为 `result` **节选**，完整字段以上表为准；未列出的字段（如 `ns*` 等）保持透传，前端按需取用即可。

### 6.6 同步日志读取 `GET /sync/logs`（同步后排障）

> 用途：同步完成后查看/排查**过程日志**（触发来源、各阶段耗时、扫描/解析明细、「无中间件应用」清单等），或提供「下载同步日志」按钮导出完整日志。服务端日志按天落盘 `api/tprel/logs/YYYY-MM-DD.log`（目录可用环境变量 `TPREL_LOG_DIR` 覆盖；同一天多次同步累积写入同一文件）。

**请求参数（Query，全可选）：**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `date` | string | 自动选最近一天有日志的日期 | 指定日期，格式 `YYYY-MM-DD` |
| `download` | string | 空 | 传 `"1"` / `"true"` 时**直接以附件下载完整日志**（不返回 JSON，浏览器触发保存）；缺省返回 JSON |

**两种模式：**

1. **默认（JSON）**：返回 `data.date / file / sizeBytes / content / truncated / files`——`content` 为指定文件**最近 256KB** 日志文本（超长时 `truncated=true`），`files` 为历史日志文件列表（`[{date,file,sizeBytes}]`，日期倒序最多 30 条），供页面做日期切换/日志面板展示。
2. **下载（`download=1`）**：服务端把 `date` 对应日志的**完整内容**以附件返回——`Content-Type: text/plain; charset=utf-8`、`Content-Disposition: attachment`、附件名固定为 `operation-topology_YYYY-MM-DD.log`。本地服务（无鉴权）可用 `<a href>` / `window.open` 直接触发保存；**生产需带 `token` 头**，请改用 `fetch`（带 `token`）取回 `blob` 后按 `Content-Disposition` 文件名触发下载（原型 `downloadSyncLog()` 即此做法）。

**curl 联调示例：**

```bash
# 默认：最近一天有日志的日期
curl -s "http://127.0.0.1:8098/api/external/operationTopology/sync/logs"

# 指定日期（须为 files 清单中存在的一天，否则 code=7「该日期无同步日志」）
curl -s "http://127.0.0.1:8098/api/external/operationTopology/sync/logs?date=2026-09-20"

# 下载完整日志（-OJ：按响应头 Content-Disposition 保存为本地文件）
curl -OJ "http://127.0.0.1:8098/api/external/operationTopology/sync/logs?download=1"

# 生产环境记得带 token
```

## 8. 数据语义须知（避免踩坑）

| 主题 | 说明 |
|---|---|
| **本地服务 vs 生产** | **本地测试服务**（`127.0.0.1:8098`）：无鉴权、数据源为 file 快照、Apollo 为 mock（`docker compose up -d`），仅供原型/联调；**生产/联调环境**：路径接口完全一致，但需 `token` 鉴权、`/sync` 会**真实抓取** EasyOps/Apollo 数据。同一套前端代码只需切换 `{BASE}` |
| **每日快照** | 每次同步覆盖当日数据，历史日期保留。查询默认取 `MAX(sync_date)` = 最近一次成功同步的日期 |
| **时区** | `syncDate` 按服务器本地时区（Asia/Shanghai）。每天 01:30 定时同步；跨天手动补跑会另生成新快照 |
| **环境 env** | 取值为部署方采集配置的环境（当前仅 **PRO**）；`/graph`、`/list`、`/detail` 均可用 `env` 过滤，不传则不按环境过滤 |
| **数据源标识** | `/graph` 返回体 `data.dataSource` = `db`（读数据库，默认）或 `file`（回退本地镜像文件） |
| **实例归属** | 每条关系带 `apolloHostId`/`apolloHostName`（来自采集的 Apollo 套）。**同一应用出现在多套实例时，其关系按实例各存一行**——这正是 `/graph` 应用节点 `apolloHosts` 含多条、页面实例筛选/搜索按归属生效的原因 |
| **节点 id** | 应用：**默认展开** `app:{apollo_app_id}\|{部署项目}\|{节点}`、**折叠** `app:{apollo_app_id}`；中间件=`mw:{类型}:{地址}`、实例=`host:{host_id}`。详情接口入参直接复用这些 id（**须与 `/graph` 同口径**），前端无需自造 |
| **机房/工程字段** | 应用节点 `node`/`engProject`、明细行 `depProject`/`ppApplication` 均由**查询期两跳关联（ADR × DPR）作为 appId 属性补充**（单值列取属性列表首值，多值走 `depProjects`/`engProjects`/`nodes`/`ppApplications` 列表，**不扩行**，此为**折叠口径** `expandDepNode=0`；**默认展开**时按部署点扩行、四列取单值、多值列表清空）；无关系数据的行仍为空，页面可直接展示与筛选（`node` 精确、`depProject` 模糊，过滤按 appId 粒度命中） |
| **连接地址** | `connectAddr` 只含 `host:port`，不含用户名/密码/库名，安全边界已保证；库名在 `mwDb`/`middlewareDb` 单独给出 |
| **数据全量性** | 采集覆盖「key 特征 + value 内容」双路径；个别 key/value 都无中间件特征的配置不会被收录（属预期） |
| **类型枚举** | 进入页面拉 `/middlewareTypes`，不要硬编码 |

## 9. 前端对接自检清单

- [ ] 基地址使用部署方提供的 `{BASE}`（文档 curl 中的 `127.0.0.1:8867` 仅为**占位**）；本地自测可换 `http://127.0.0.1:8098`（无需鉴权，见 §1.1）
- [ ] 请求头用 `token: <jwt>`（无 Bearer 前缀）；收到 `reload:true` 跳登录；收到 `new-token` 响应头则更新本地 token
- [ ] 成功判定统一按 `code === 0`（含列表信封，`list` 的 `code` 同为数字 `0`）
- [ ] 拓扑主视图只用 `data.nodes` + `data.edges`；渲染 key 用 `node.id`；实例层节点与归属边由前端按 `apolloHosts` 生成
- [ ] 中间件节点角标 = `depCount`；「被谁依赖」高亮 = `appIds`
- [ ] 点击节点 → 用 `node.id` 调 `/detail` 渲染详情面板（按 `category` 分组展示字段）
- [ ] `nodes` 为空展示空态 + 「手动同步」引导
- [ ] 「手动同步」仅作入口：打开弹窗并先查询 `/sync/status`（**不直接 `POST /sync`**）；空闲时弹窗内才提供「开始同步」，点击后提交
- [ ] `/sync` 提交后轮询 `/sync/status` 展示**进度条**（原型 1s；**生产建议 3~5s**，避免每秒写一行操作日志）：`running=true` 时**不提供开始按钮**（全局单实例）并按 `data.percent`/`data.stageText` 渲染（`percent=-1` 走不确定滑动动画）；完成后 `data.result.partial:true` 且已有旧快照 → **不覆盖**、页面保持旧版数据并提示「已保留现有快照」，无旧快照才落部分数据并提示「本次为部分结果」
- [ ] 弹窗可随时关闭（后台任务不中断）；重新打开先查询状态——执行中自动恢复进度轮询，空闲展示最新结果/失败/起始面板
- [ ] 筛选（env/middlewareType）变化时重新拉 `/graph`；类型下拉用 `/middlewareTypes`；应用/实例搜索在 `nodes` + 顶层 `apolloHosts` 上做前端本地模糊匹配
- [ ] 数据源徽标：读 `/graph` 返回体 `data.dataSource`（`db`=数据库，`file`=本地镜像兜底；**已无 `X-Data-Source` 响应头**）
- [ ] 同步结果如需展示类型分布，读取 `result.nodeStats`（节点数）/`result.typeStats`（关系数）；如需展示「无中间件应用 N 个」，读取 `result.noMiddlewareCount` 并可展开 `result.noMiddlewareApps`（appId+名称；口径：已扫描未发现中间件关系、不含未完成/未执行应用）
- [ ] 跳① 异常提示：`result.relationErr=true` 时展示 `result.relationMsg`（如「关系表 app_dp_relation 不存在，未落库（启动时 AutoMigrate 未建表，请检查 DB 连接与权限）」）；主表同步仍成功，页面拓扑数据不受影响
- [ ] 同步后排障可调 `GET /sync/logs`：默认 JSON 看日志内容（`?date=` 切日期），`download=1` 直接下载完整日志（浏览器保存文件，无需按信封解析）；建议入口放在同步结果面板（原型置于弹窗右上角，与底部主操作区分），日志查看默认**非全屏**并提供「全屏」切换
- [ ] 联调前先用各接口小节末尾的 curl 在部署环境自验（graph/detail/list/sync、sync/status、sync/logs、middlewareTypes），确认 `{BASE}`、token、env 可用后再开始页面开发（注意 `/list` 分页为 `id` 倒序）
- [ ] 图节点渲染按 §3.3：key 用 `id`，应用节点按 `apolloHosts` 生成实例层，`appIds`/`depCount` 用于中间件高亮与角标；**勿依赖 `depProject` 字段**（图返回中没有）
- [ ] 中文/特殊字符的 Query 值记得 `encodeURIComponent`（如按实例名 `apolloHostName=广州…` 搜索）
