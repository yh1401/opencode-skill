## 三、建议阅读顺序

1. **先建立全局印象**：[运维关系拓扑图方案.md](./运维关系拓扑图方案.md) §1–§4（为什么做、整体架构、数据模型、数据怎么来）。
2. **再看端到端怎么跑**：[拓扑查询总体逻辑.md](./拓扑查询总体逻辑.md) §0 全景总览 + §10 调用链时序。
3. **需要动手**：改后端看[接口逻辑说明.md](./接口逻辑说明.md)，前端看[前端对接说明.md](./前端对接说明.md)，联调看 [curl-接口测试文档.md](./curl-接口测试文档.md)。
4. **要建表/改字段**：只认[运维拓扑.md](./运维拓扑.md) §2。

## 四、约定

- **DDL 只有一份**：[运维拓扑.md](./运维拓扑.md) §2 为权威定义，其他文档中出现的建表语句一律视为历史残留，以该处为准。
- **路径引用一律用相对路径**，便于文档随代码一起迁移。
- **真实样本不放运行目录**：`业务数据/` 下文件禁止改名为 `../data/*.json`（运行时会作为数据源加载）。
- **运行日志与测试归档**在 [../logs/README.md](../logs/README.md)，本目录不写日志细节。
