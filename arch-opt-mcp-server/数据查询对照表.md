# 架构优化智能体 · 数据查询对照表

> 版本：2.0.0　|　适用范围：`arch-opt-mcp-server` 全部 MCP 工具
> 本文说明每个分析维度的**数据来源、查询语句、判定口径**，供开发/运维排查与口径核对使用。

## 一、数据源概览

系统只有两个数据源，全部经 `ArchDataClient` 统一封装（超时 8s、重试 1 次、失败可 Mock 降级）。

| 数据源 | 用途 | 调用方式 | 地址来源 |
|--------|------|----------|----------|
| **统一拓扑代理** | 模块/节点/项目/宿主机/链路等业务数据 | POST 网关，透传目标业务接口 | [datasources.json](config/datasources.json) `proxy` |
| **Prometheus** | 容器运行指标 | GET `/api/v1/query?query=<PromQL>` | [datasources.json](config/datasources.json) `prometheus` |

### 1.1 统一拓扑代理请求格式

```
POST {proxy.url}
{
  "url": "<业务接口 URL>",
  "types": "GET|POST",
  "provinceDetail": { "province": "大模型", "appId": "...", "appSecret": "..." },
  "reqParam": { ...业务接口入参... }
}
```

代理网关：`https://easyviews.tech.ctseelink.cn/api/third/thirdAuth/getTykjProvince`
凭据 `appId`/`appSecret` 由环境变量 `ARCH_APP_ID` / `ARCH_APP_SECRET` 注入。

### 1.2 业务接口清单

| 接口 key | URL | 方法 | 说明 |
|----------|-----|------|------|
| `getTopologyByProductName` | `/api/autoOperation/topology/getTopologyByProductName` | GET | 模块与应用归属 |
| `getTopologyByNodeProject` | `/api/autoOperation/topology/getTopologyByNodeProject/` | POST | 服务链路与依赖拓扑 |
| `getNode` | `/api/external/monitorData/getNode` | GET | 节点列表 |
| `getVirtualStructure` | `/api/external/monitor/getVirtualStructure` | GET | 物理机 ↔ 云主机关系 |
| `getTopologyInfo` | `/api/external/monitorData/getTopologyInfo` | GET | 项目 ↔ 云主机部署关系 |

## 二、维度 → 数据源 → 查询 对照总表

| 维度 | MCP 工具 | 数据源 | 查询方式 | 关键指标 / 接口 | 判定阈值 |
|------|----------|--------|----------|-----------------|----------|
| 入口 | `mcp_module_topology` | 拓扑代理 | `getTopologyByProductName` | `node` + `productName` | — |
| D1 副本数量与可用性 | `mcp_replica` | Prometheus | 2 条即时查询 | `kube_deployment_spec_replicas`、`..._status_replicas_available` | `min_replicas=2` |
| D2 容量瓶颈 | `mcp_capacity` | Prometheus | 3 组窗口查询 | CPU 限流 / 内存使用率 / HPA 达上限 | CPU>20%、内存>85%、15min |
| D3 负载不均衡 | `mcp_load_balance` | Prometheus | 1 条窗口查询 | 最大/平均 CPU 比 | `>2.0`、15min |
| D4 OOM | `mcp_oom` | Prometheus | 2 条查询 | `..._last_terminated_reason`、`..._restarts_total` | 近 7 天 |
| D5 链路依赖 | `mcp_link_dependency` | 拓扑代理 | `getTopologyByNodeProject` | `nodes` / `edges` | 阈值待制定 |
| D6 故障域（辅助） | `mcp_node_list` | 拓扑代理 | `getNode` | 云公司前缀节点 + `ctyun_node_code3` | — |
| D6 故障域（辅助） | `mcp_virtual_structure` | 拓扑代理 | `getVirtualStructure` | `ipData` 物理机→云主机 | — |
| D6 故障域（辅助） | `mcp_topology_info` | 拓扑代理 | `getTopologyInfo` | `projectIpData` 项目→云主机 | — |
| D6 故障域 | `mcp_fault_domain` | 拓扑代理 | 串联上面 3 个接口 | 项目→云主机→宿主机集中度 | 同宿主机即 🟥；集中>50% 🟥 |

> 说明：D1~D4 若未显式传 `deployments`，会先调用 `mcp_module_topology` 自动派生 `-dep` 结尾应用列表。

## 三、逐维度详细查询语句

### 入口：`mcp_module_topology`
- **接口**：`getTopologyByProductName`
- **入参**：`{ "center": "true", "node": "<节点>", "productName": "天翼看家" }`
- **取值路径**：`data[].topologyData.nodes[]` → `nameCn` / `name` / `objectType` / `projectName[]`
- **产出**：`deploy_node`（供 D5 用）、`-dep` 应用清单（供 D1~D4 派生）
- **筛选规则**：仅 `projectName` 以 `-dep` 结尾的应用进入容器检查，其余标 ⚪ 不适用

### D1 副本数量与可用性 `mcp_replica`
```promql
kube_deployment_spec_replicas{cmdb_node="<node>"}
kube_deployment_status_replicas_available{cmdb_node="<node>"}
```
- **判定**：`spec < min_replicas(2)` → 🟥；`available < spec` → 🟥

### D2 容量瓶颈 `mcp_capacity`
```promql
# ① CPU 限流比例（窗口 15m）
rate(container_cpu_cfs_throttled_seconds_total{deployment="<dep>"}[15m])
  / rate(container_cpu_cfs_periods_total{deployment="<dep>"}[15m])

# ② 内存使用率
container_memory_working_set_bytes{deployment="<dep>"}
  / kube_pod_container_resource_limits_memory_bytes{deployment="<dep>"}

# ③ HPA 是否达最大副本
kube_horizontalpodautoscaler_status_current_replicas{deployment="<dep>"}
  == kube_horizontalpodautoscaler_spec_max_replicas{deployment="<dep>"}
```
- **判定**：① > 20% → 🟥；② > 85% → 🟥（limit 缺失/为 0 → 🟨）；③ 命中 → 🟥，无记录 → ⚪

### D3 负载不均衡 `mcp_load_balance`
```promql
max(rate(container_cpu_usage_seconds_total{deployment="<dep>"}[15m])) by (deployment)
  / avg(rate(container_cpu_usage_seconds_total{deployment="<dep>"}[15m])) by (deployment)
```
- **判定**：比值 > 2.0 → 🟥

### D4 OOM `mcp_oom`
```promql
kube_pod_container_status_last_terminated_reason{deployment="<dep>",reason="OOMKilled"} == 1
kube_pod_container_status_restarts_total{deployment="<dep>"}
```
- **判定**：命中 OOMKilled 且有重启证据 → 🟥；窗口默认近 7 天（`lookback_days`，待业务确认）

### D5 链路依赖 `mcp_link_dependency`
- **接口**：`getTopologyByNodeProject`
- **入参**：
```json
{ "center": "true", "calleeRange": 1, "callerRange": 1,
  "filterNode": false, "minute": 5, "nodeType": "",
  "node": "<deploy_node>", "projects": ["<应用>"] }
```
- **取值路径**：`data.nodes[]`、`data.edges[]`
- **分析产出**：按边入度统计集中依赖（入度 ≥ 2）
- **判定**：错误率 / 慢调用阈值未定 → 只返回统计，不做 🟥 判定

### D6 省节点故障域 `mcp_fault_domain`（三层链式）
| 步骤 | 接口 | 关键入参 | 取值 | 产出 |
|------|------|----------|------|------|
| 1 | `getNode` | `{center:"true"}` | 筛「云公司」前缀节点 | `ctyun_node_code3` |
| 2 | `getVirtualStructure` | `{center:"true", node:"<code3>"}` | `data.ipData` | 反转为 `vm_to_host` |
| 3 | `getTopologyInfo` | `{center:"true", node:"<节点>"}` | `data.projectIpData` | 项目→云主机 IP 列表 |

- **判定**：对每个项目统计宿主机分布
  - 全部实例同宿主机 → 🟥
  - 最大宿主机集中比例 > 50% → 🟥
  - 部分云主机未映射宿主机 → 🟨（集中度仅供参考）
- **数据缺口**：`ctyun_node_code3` 为空 → 第 2 步无映射 → 整体 🟨，仅输出已知部署分布

## 四、结果四态

| 状态 | 标识 | 含义 |
|------|------|------|
| `risk` | 🟥 | 已发现风险（阈值命中，含证据） |
| `ok` | 🟩 | 未触发规则 |
| `insufficient` | 🟨 | 数据不足（接口失败 / 指标缺失 / 映射中断） |
| `not_applicable` | ⚪ | 不适用（无 HPA、非 -dep 应用等） |

每条结果均带 `collected_at`（采集时间）与 `rule_version`（规则版本）以便溯源。

## 五、阈值来源

所有判定阈值集中在 [thresholds.json](config/thresholds.json)（version 2.0.0），改此文件即可调整口径，无需改代码或模板：

| 分组 | 关键项 | 默认值 | 状态 |
|------|--------|--------|------|
| `replica` | `min_replicas` | 2 | 已确认（至少 2 副本，2026-10-19） |
| `capacity` | `cpu_throttle_ratio` / `memory_usage_ratio` / `duration_minutes` | 0.20 / 0.85 / 15 | 已定稿 |
| `load_balance` | `max_avg_ratio` / `duration_minutes` | 2.0 / 15 | 已定稿 |
| `oom` | `lookback_days` | 7 | 待业务确认 |
| `link_dependency` | `error_rate_threshold` / `slow_call_threshold_ms` | null | 待联调制定 |
| `fault_domain` | `min_instance_to_check` | 1 | 已定稿 |
| `container_check` | `dep_suffix_filter` | true | 第一阶段仅 -dep 应用 |

## 六、数据缺口说明

以下情况统一返回 🟨「信息不足」，**不得**推断为「无风险」：

1. 业务接口失败或返回 `code != 0`
2. Prometheus 指标为空（如未开启对应 exporter）
3. 内存 limit 缺失或为 0
4. 节点 `ctyun_node_code3` 为空，无法建立宿主机映射
5. 云主机 IP 未能在 `vm_to_host` 中匹配到宿主机
