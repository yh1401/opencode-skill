## 二、执行原理详解

### 2.1 路由策略

Skill Agent 采用**基于语义理解的智能路由策略**，所有子技能为**平行关系**，不存在层级或优先级划分。

#### 核心路由流程

```
用户输入
    │
    ├─→ [1] 语义分析引擎
    │       ├─ 提取核心语义 (查询服务器)
    │       ├─ 提取实体信息 (贵州、机房)
    │       └─ 生成置信度分数
    │
    └─→ [2] 技能匹配引擎
            ├─ 遍历注册中心所有技能
            ├─ 计算匹配置信度
            └─ 选择最优匹配技能
```

### 2.2 技能匹配算法

```python
# 伪代码示例
def match_skill(user_input):
    skills = load_skills_from_registry()  # 从 skills.json 加载
    best_skill = None
    highest_score = 0
    
    for skill in skills:
        if not skill.enabled:  # 跳过禁用的技能
            continue
        
        # 语义匹配
        semantic_score = semantic_match(user_input, skill.description)
        
        # 关键词匹配
        keyword_score = keyword_match(user_input, skill.keywords)
        
        # 综合得分
        total_score = semantic_score * 0.6 + keyword_score * 0.4
        
        if total_score > highest_score:
            highest_score = total_score
            best_skill = skill
    
    return best_skill
```

### 2.3 歧义处理机制

当多个技能匹配置信度接近时：

1. **触发条件**: 置信度差值 < 0.1
2. **处理策略**:
   - 追问用户明确意图
   - 提供选项列表供用户选择

## 五、错误处理机制

### 5.1 异常处理流程

```
┌─────────────────┐
│   API 调用失败   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  检查错误类型    │
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
┌────────┐ ┌────────┐
│网络错误│ │业务错误│
└───┬────┘ └───┬────┘
    │          │
    ▼          ▼
┌────────┐ ┌────────┐
│重试1次│ │返回错误│
└───┬────┘ └───┬────┘
    │          │
    ▼          ▼
┌────────┐ ┌────────┐
│重试成功│ │记录日志│
└────────┘ └────────┘
```

### 5.2 常见错误处理

| 错误类型 | 错误代码 | 处理策略 |
|---------|---------|----------|
| 连接失败 | ECONNREFUSED | 提示检查服务器状态 |
| 请求超时 | ETIMEDOUT | 重试1次，仍失败返回超时提示 |
| 参数校验失败 | VALIDATION_ERROR | 提示用户修正参数 |
| 无权限 | 401/403 | 返回权限不足提示 |
| 服务器错误 | 500 | 返回服务异常提示 |

## 六、总结

### 6.1 数据流转关键点

1. **用户层**: 自然语言输入
2. **主技能层**: 意图识别 + 技能路由
3. **注册中心层**: 技能元数据管理
4. **子技能层**: 参数提取 + API 调用
5. **MCP 层**: 协议转换
6. **数据服务层**: Mock 数据查询

### 6.2 核心设计特点

| 特点 | 说明 |
|------|------|
| **平行匹配** | 所有技能平等，基于语义选择最优 |
| **配置驱动** | 参数映射通过 YAML 配置管理 |
| **Mock 支持** | 开发阶段使用 Mock 数据 |
| **统一输出** | 所有结果以 Markdown 表格返回 |
| **层次清晰** | 职责分离，易于维护 |

### 6.3 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 路由匹配时间 | < 100ms | 语义分析 + 技能匹配 |
| API 调用时间 | < 200ms | MCP 服务器响应 |
| 端到端延迟 | < 500ms | 用户输入到结果返回 |
| 并发能力 | 100+ QPS | 支持多用户并发 |
