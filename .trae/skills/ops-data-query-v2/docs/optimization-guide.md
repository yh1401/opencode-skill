# Skill Agent 优化思路与实现方案

## 一、当前状态分析

### 1.1 架构评估

从 Agent 平台视角分析，当前 `skill-agent` 的设计存在以下问题：

| 问题类型 | 当前状态 | 影响 |
|----------|----------|------|
| **执行流程缺失** | 没有明确的执行步骤定义 | Agent 不知道如何一步步执行技能 |
| **参数解析依赖 YAML** | 参数映射规则在 `params.yaml` 中 | Dify 无法解析 YAML，导致参数映射失效 |
| **技能路由模糊** | 路由逻辑依赖自然语言描述 | Agent 可能误判技能匹配 |
| **输出格式不统一** | 缺少输出规范 | 返回结果格式混乱，可读性差 |
| **错误处理薄弱** | 仅有简单降级机制 | 无法优雅处理各种错误场景 |
| **技能边界不清** | 子技能之间存在功能重叠 | 如 `cmdb-server-query` 和 `server-public-ip-query` |

### 1.2 执行流程问题（核心痛点）

当前技能的执行完全依赖 Agent 的"理解能力"，没有给出**明确的步骤指引**：

```
用户查询 → [Agent 自行理解] → 调用 API → 返回结果
             ↑
        问题所在：Agent 可能误解意图
```

---

## 二、优化目标

### 2.1 核心原则

1. **声明式定义**：技能的执行流程应该是声明式的，而非依赖 Agent 的隐式理解
2. **结构化 Schema**：输入/输出应该有明确的 Schema 定义
3. **可执行性**：技能文档本身应该包含可执行的步骤定义
4. **健壮性**：具备完整的错误处理和降级机制

### 2.2 优化后的执行模型

```
用户查询
    ↓
[Step 1] 意图识别 → 匹配子技能
    ↓
[Step 2] 参数提取 → 从用户输入中提取参数
    ↓
[Step 3] 参数校验 → 校验参数合法性
    ↓
[Step 4] API调用 → 调用后端接口
    ↓
[Step 5] 结果转换 → 转换为用户友好格式
    ↓
[Step 6] 输出响应 → 返回最终结果
```

# Skill Agent - 智能运维数据查询代理

## 执行流程

当用户发起查询请求时，按照以下步骤执行：

### Step 1: 意图识别

根据用户输入，从以下技能中选择最匹配的一个：

| 技能 ID | 功能描述 | 触发关键词 |
|---------|----------|------------|
| cmdb-server-query | 查询服务器配置信息 | 服务器、主机、机房、IP |
| server-public-ip-query | 查询服务器公网IP | 公网IP、外网IP、带宽 |
| project-deployment-query | 查询项目部署记录 | 部署、上线、发布、版本 |
| product-query | 查询产品信息 | 产品、产品线、产品ID |
| project-basis-query | 查询项目基础信息 | 项目、代码、仓库、SVN |

**匹配规则**：
1. 优先匹配最具体的关键词（如"公网IP" > "IP"）
2. 如果多个技能都匹配，选择最精确的一个
3. 如果无法匹配，询问用户明确需求

### Step 2: 参数提取

根据匹配的技能，从用户输入中提取参数：

**通用参数提取规则**：
- 数量词提取："一台"→1, "几台"→15, "所有"→100
- 机房名称映射："贵州"→"云公司->贵州", "北京"→"云公司->北京"
- 状态映射："在线"→"0", "库存"→"1"
- IP提取：识别 IPv4 格式的地址

### Step 3: 参数校验

校验提取的参数是否合法：
- 必填参数是否完整
- 参数值是否在允许范围内
- 分页参数是否合理

### Step 4: API 调用

调用对应的 API 接口：
- 使用 POST 方法
- Content-Type: application/json
- 超时时间：30秒

### Step 5: 结果转换

将 API 返回的原始数据转换为用户友好的格式：
- 将状态码转换为中文（如"0"→"在线"）
- 格式化表格展示
- 添加必要的说明信息

### Step 6: 输出响应

按照统一格式输出查询结果：
- 包含查询条件
- 包含结果摘要
- 包含详细数据表格
- 如有异常，包含错误说明

## 错误处理

### 场景一：技能匹配失败

**处理方式**：
1. 明确告知用户无法识别意图
2. 列出可用的技能和示例
3. 引导用户重新输入

**输出示例**：
```
抱歉，我无法识别您的查询意图。

当前可用的查询技能：
1. 服务器查询 - 如"查询贵州机房的服务器"
2. 公网IP查询 - 如"查询服务器的公网IP"
3. 部署查询 - 如"查询项目的部署记录"
4. 产品查询 - 如"查询产品信息"
5. 项目查询 - 如"查询项目代码仓库"

请重新描述您的需求。
```

### 场景二：参数提取失败

**处理方式**：
1. 明确告知缺少的参数
2. 询问用户补充信息

**输出示例**：
```
我需要更多信息来完成查询：
- 请提供机房位置（如贵州、北京、上海、广州）

您可以补充说："查询贵州机房的服务器"
```

### 场景三：API 调用失败

**处理方式**：
1. 尝试重试（最多3次）
2. 如果仍然失败，降级返回 Mock 数据
3. 明确标记为模拟数据

**输出示例**：
```
⚠️ 提示：当前网络环境无法访问真实数据，已切换为模拟数据。

查询结果：
...（Mock数据表格）...
```

# CMDB 服务器查询技能

## 功能描述

本技能用于查询服务器的详细配置信息，包括：
- 基本信息：主机名、IP地址、机房位置
- 硬件配置：CPU核数、内存大小、服务器类型
- 运行状态：在线状态、所属环境
- 业务信息：所属产品、项目、负责人

## 触发条件

当用户查询包含以下关键词时触发：
- 服务器、主机、机器、设备
- 机房、数据中心、位置
- IP地址、内网IP
- 配置、规格、硬件

**排他条件**：
- 如果用户明确提到"公网IP"，应触发 `server-public-ip-query` 技能
- 如果用户明确提到"部署"，应触发 `project-deployment-query` 技能

### 3.2 移除 YAML 配置依赖

#### 3.2.1 问题分析

当前技能依赖 `config/params.yaml` 和 `config/api.yaml` 来定义参数映射和 API 配置，但 Dify 平台**无法解析 YAML 文件**，导致：
- 参数映射规则失效
- API 地址配置无法被读取
- Agent 只能通过阅读 SKILL.md 来理解配置

#### 3.2.2 解决方案

将 YAML 配置内容**整合到 SKILL.md 文档中**，使用表格和列表形式呈现，便于 Agent 理解和使用。

**步骤**：
1. 删除 `config/params.yaml`，将参数映射规则写入 SKILL.md
2. 删除 `config/api.yaml`，将 API 配置写入 SKILL.md
3. 更新所有引用的文档

        └── 否 → 返回 Mock 数据（标记为模拟数据）
```

### 3.5 技能边界清晰化

#### 3.5.1 当前问题

`cmdb-server-query` 和 `server-public-ip-query` 存在功能重叠，都可以查询服务器的 IP 信息。

#### 3.5.2 解决方案

| 技能 | 职责范围 | 边界 |
|------|----------|------|
| cmdb-server-query | 查询服务器的**基本配置信息**（主机名、IP、硬件、状态等） | 不包含公网 IP 的详细网络信息 |
| server-public-ip-query | 查询服务器的**公网网络信息**（公网 IP、带宽、负载均衡等） | 不包含服务器硬件配置信息 |

**路由规则**：
- 如果用户提到"公网IP"、"外网"、"带宽"等关键词，优先匹配 `server-public-ip-query`
- 如果用户仅查询服务器基本信息，匹配 `cmdb-server-query`

### 7.2 技能注册机制（registry/skills.json）分析

#### 7.2.1 当前作用评估

**Agent 平台实际使用情况**：
- ✅ **平台依赖**：Dify 等平台确实需要 skills.json 来发现和注册技能
- ✅ **关键词匹配**：平台会使用 keywords 字段进行初步的技能匹配
- ❌ **版本不一致**：skills.json 中技能版本为 `1.0.0`，但各子技能 SKILL.md 已升级为 `2.0.0`
- ❌ **缺少路由优先级**：路由优先级定义在主技能 SKILL.md 中，注册中心无法感知

#### 7.2.2 改进建议

**方案一：增强注册中心字段**

扩展 skills.json，增加路由优先级、触发条件等字段：

```json
{
  "version": "2.0",
  "lastUpdated": "2026-06-18",
  "description": "技能元数据注册中心",

    {
      "id": "cmdb-server-query",
      "name": "CMDB服务器查询",
      "description": "查询CMDB服务器信息，支持按机房、状态、类型等多条件组合查询",

}

**新增字段说明**：

**推荐方案**：方案一，增强注册中心字段，使其成为路由决策的权威数据源。
