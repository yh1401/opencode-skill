# Skill Agent - 智能运维数据查询代理

## 执行流程

当用户发起查询请求时，按照以下步骤执行：

### Step 1: 意图识别

根据用户输入，从以下技能中选择最匹配的一个：

| 技能 ID | 功能描述 | 触发关键词 |
|---------|----------|------------|
| cmdb-server-query | 查询服务器配置信息 | 服务器、主机、机房、IP、配置 |
| server-public-ip-query | 查询服务器公网IP | 公网IP、外网IP、带宽、出口IP |
| project-deployment-query | 查询项目部署记录 | 部署、上线、发布、版本、部署记录 |
| product-query | 查询产品信息 | 产品、产品线、产品ID、产品名称 |
| project-basis-query | 查询项目基础信息 | 项目、代码、仓库、SVN、GIT |

**匹配规则**：
1. 优先匹配最具体的关键词（如"公网IP" > "IP"）
2. 如果多个技能都匹配，选择最精确的一个
3. 如果无法匹配，询问用户明确需求

### Step 2: 参数提取

根据匹配的技能，从用户输入中提取参数：

**通用参数提取规则**：
- 数量词提取："一台"→1, "几台"→15, "所有"→100
- 机房名称映射："贵州"→"云公司->贵州", "北京"→"云公司->北京", "上海"→"省公司->上海", "广州"→"云公司->广州"
- 状态映射："在线"→"0", "库存"→"1"
- IP提取：识别 IPv4 格式的地址
- 时间范围：识别"从A到B"格式的时间范围

### Step 3: 参数校验

校验提取的参数是否合法：
- 必填参数是否完整
- 参数值是否在允许范围内
- 分页参数是否合理（pageSize 1~100）

### Step 4: API 调用

调用对应的 API 接口：
- 使用 POST 方法
- Content-Type: application/json
- 超时时间：30秒
- 重试次数：最多3次

### Step 5: 结果转换

将 API 返回的原始数据转换为用户友好的格式：
- 将状态码转换为中文（如"0"→"在线"）
- 格式化表格展示
- 添加必要的说明信息

### Step 6: 输出响应

按照统一格式输出查询结果：
- 包含查询条件
- 包含结果摘要
- 包含详细数据表格
- 如有异常，包含错误说明

## 技能路由优先级

| 优先级 | 技能 ID | 说明 |
|--------|---------|------|
| 1 | server-public-ip-query | 明确提到"公网IP"、"外网"时优先匹配 |
| 2 | project-deployment-query | 明确提到"部署"、"发布"、"上线"时优先匹配 |
| 3 | product-query | 明确提到"产品"、"产品线"时优先匹配 |
| 4 | project-basis-query | 明确提到"项目"、"代码"、"仓库"时优先匹配 |
| 5 | cmdb-server-query | 通用服务器查询，作为兜底匹配 |

```
    ▼
```

### 关键词匹配规则

| 目标技能 | 匹配关键词 | 接口能力 |
|----------|------------|----------|
| project-deployment-query | 部署、部署记录、部署状态、部署历史、部署版本、部署时间 | 项目部署查询 |
| server-public-ip-query | 公网IP、外网IP、出口IP、带宽、网络类型 | 服务器公网IP查询 |
| project-basis-query | 工程项目、SVN、GIT、项目代码、项目路径 | 工程项目查询 |
| cmdb-server-query | 服务器、主机、机房、IP地址、CPU、内存 | CMDB服务器查询 |
| product-query | 产品、产品线、产品名称、产品信息 | 产品查询 |

### 组合冲突解决矩阵

当用户输入包含多个技能相关关键词时，按照以下规则进行冲突解决：

| 用户输入 | 核心意图判断 | 匹配技能 | 原因分析 |
|---------|-------------|---------|---------|
| "查询项目部署的服务器信息" | 查询部署记录 | project-deployment-query | 出现"部署"且意图是查部署，优先级最高 |
| "查询公网IP对应的服务器" | 查询公网IP | server-public-ip-query | 出现"公网IP"，意图是查公网IP |
| "查询服务器的公网IP" | 查询公网IP | server-public-ip-query | 虽有"服务器"，但核心意图是查公网IP |
| "查询项目的SVN路径" | 查询工程项目 | project-basis-query | 出现"SVN"，意图是查项目代码 |
| "查询产品的服务器" | 查询服务器 | cmdb-server-query | 虽有"产品"，但核心意图是查服务器 |
| "服务器和部署都查一下" | 意图不明确 | 询问用户 | 需要用户明确先查哪个 |

## 错误处理

### 场景一：技能匹配失败

**处理方式**：
1. 明确告知用户无法识别意图
2. 列出可用的技能和示例
3. 引导用户重新输入

**输出示例**：
```
抱歉，我无法识别您的查询意图。

当前可用的查询技能：
1. 服务器查询 - 如"查询贵州机房的服务器"
2. 公网IP查询 - 如"查询服务器的公网IP"
3. 部署查询 - 如"查询项目的部署记录"
4. 产品查询 - 如"查询产品信息"
5. 项目查询 - 如"查询项目代码仓库"

请重新描述您的需求。
```

### 场景二：参数提取失败

**处理方式**：
1. 明确告知缺少的参数
2. 询问用户补充信息

**输出示例**：
```
我需要更多信息来完成查询：
- 请提供机房位置（如贵州、北京、上海、广州）

您可以补充说："查询贵州机房的服务器"
```

### 场景三：API 调用失败

**处理方式**：
1. 尝试重试（最多3次）
2. 如果仍然失败，降级返回 Mock 数据
3. 明确标记为模拟数据

**输出示例**：
```
⚠️ 提示：当前网络环境无法访问真实数据，已切换为模拟数据。

查询结果：
...（Mock数据表格）...
```

## 上下文感知规则

### 上下文保留

在多轮对话中，系统会保留以下关键参数，有效期为 5 分钟：

| 参数类型 | 保留内容 | 有效期 |
|----------|----------|--------|
| 机房位置 | 最近一次查询的机房位置（如"云公司->贵州"） | 5分钟 |
| 项目名称 | 最近一次查询的项目名称（如"guizh-rules-api"） | 5分钟 |
| 产品名称 | 最近一次查询的产品名称（如"规则引擎平台"） | 5分钟 |
| 查询技能 | 最近一次使用的技能 ID | 5分钟 |

### 上下文使用

当用户未明确指定参数时，系统自动继承上下文：

```
用户1：查询贵州机房的服务器
→ 使用 node="云公司->贵州"

用户2：查询在线的
→ 自动继承 node="云公司->贵州"，查询贵州机房的在线服务器

用户3：查询北京的
→ 覆盖上下文，使用 node="云公司->北京"
```

### 上下文重置

以下情况会触发上下文重置：
- 用户明确使用"新的"、"重新"、"重置"等关键词
- 超过 5 分钟无交互
- 用户切换到不同类型的查询（如从服务器查询切换到部署查询）

## 参数组合规则

### 互斥参数

某些参数不能同时使用：

| 参数组 | 说明 |
|--------|------|
| ip, hostName, assetNo, serial | 最多指定一个模糊匹配参数 |

### 依赖参数

某些参数需要其他参数先行指定：

| 参数 | 依赖条件 |
|------|----------|
| isReplaceForChinaProduction | 需要先指定 isFromOutside="1" |

### 推荐组合

根据常见场景，推荐以下参数组合：

| 场景 | 推荐参数组合 | 示例 |
|------|-------------|------|
| 查询机房服务器 | node + state | 贵州机房的在线服务器 |
| 查询特定服务器 | ip 或 hostName | 主机名包含 prod 的服务器 |
| 查询产品服务器 | productName + environment | 规则引擎平台的生产服务器 |
| 查询部署记录 | name + deployEnv | guizh-rules-api 的生产部署 |

## 大数据量处理策略

### 触发条件

当查询结果超过 50 条时，自动触发大数据量处理策略。

### 处理方式

1. **显示控制**：仅显示前 20 条记录
2. **分页导航**：提供分页信息和导航提示
3. **筛选建议**：提供更精确的筛选条件建议

### 输出示例

```markdown

**查询条件**：查询贵州机房的服务器

**匹配技能**：CMDB服务器查询

---

**结果摘要**：共查询到 256 台服务器，显示前 20 条

| 主机名 | IP地址 | 状态 | CPU | 内存 |
|--------|--------|------|-----|------|
| gz-server-01 | 192.168.7.101 | 在线 | 32核 | 128GB |

**导航提示**：
- 当前显示第 1 页，共 13 页

**筛选建议**：
```

## 快速开始

### 在 Dify 中使用

1. 将 `skill-agent/` 打包为 `skill-agent.zip`
2. 在 Dify skill 管理页面上传
3. 系统自动解析 `registry/skills.json` 加载所有技能
4. 用户可以通过自然语言查询，系统自动匹配对应技能

### 打包

```bash
bash package.sh
```

## 扩展新技能

1. 在 `skills/` 下创建新目录 `new-skill/`
2. 编写 `SKILL.md`（包含完整的功能描述、参数映射、API定义、输出格式）
3. 在 `registry/skills.json` 中注册
