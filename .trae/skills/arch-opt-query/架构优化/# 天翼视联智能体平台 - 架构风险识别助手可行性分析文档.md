# 天翼视联智能体平台 - 架构风险识别助手可行性分析文档
> 文档用途：平台方案评审，用于开发立项评估；目标：在天翼视联智能体平台开发架构风险识别助手，**每日定时生成架构风险识别日志**
> 识别范围：贵州/广州多AZ中心节点模块、省节点；数据源：Prometheus、Pinpoint、CMDB元数据、K8s API

## 1 业务需求概述
### 1.1 识别对象
**中心节点**
- 贵州6模块：核心业务API、设备信令调度、直播服务网关、设备告警、云眼核心业务、设备云存上传
- 广州多AZ7模块：核心业务API、设备信令调度、直播服务网关、设备告警、云眼核心业务、设备云存上传（苏州）、消息中心4.0

> 业务模块与K8s Deployment应用名称映射关系，通过CMDB外部接口获取。

### 1.2 风险识别规则清单
| 风险类型 | 判定规则 |
| ---- | ---- |
| 单点部署风险 | Deployment副本数≤2；期望副本数 ≠ 可用副本数 |
| CPU限流风险 | CPU限流周期比例＞20%，持续15min；关联调用延迟辅助判断 |
| 内存容量风险 | 工作集内存 / 有效内存limit＞85%，持续15min |
| 扩容容量风险 | HPA已经触达最大副本，业务/资源负载持续走高 |
| Pod负载不均衡 | 同Deployment下Pod：最大CPU负载 / 平均负载＞2，持续15min |
| OOM稳定性风险 | 存在OOMKilled事件，同时伴随Pod重启 |
| 链路依赖风险（Pinpoint） | 服务拓扑识别：集中依赖、下游依赖过多、长调用链、异常慢调用、上下游影响、关键依赖、循环依赖 |
| 省节点服务亲和性风险 | 多副本Pod大量调度到同一宿主机，存在单点硬件故障风险 |

### 1.3 输出产物
每日定时生成架构风险识别日志（结构化JSON日志）
日志内容：风险ID、风险类型、风险等级、业务模块、cmdb节点、namespace、deployment/pod名称、判定依据、原始指标值、优化建议。

### 1.4 数据源清单
| 数据源 | 作用 |
|---|---|
| Prometheus（kube-state-metrics、cAdvisor、node-exporter） | 获取Deployment副本、CPU限流、内存工作集、HPA状态、Pod负载、OOM事件、Pod节点调度信息 |
| CMDB接口 | 获取环境env、deployment与业务模块映射、cmdb_node信息，实现业务模块视角归类 |
| Pinpoint API | 获取服务调用拓扑、调用耗时、错误率、服务依赖关系 |
| K8s API | Pod事件（OOMKilled、容器重启）、Pod亲和/反亲和策略配置信息 |

## 2 可行性分析
### 2.1 ✅ 有利条件（可行性支撑点）
1. **指标规则可落地，K8s资源类风险可通过PromQL实现**
    - 单点部署风险：`kube_deployment_spec_replicas`（期望副本）、`kube_deployment_status_replicas_available`（可用副本），结合CMDB标签筛选生产环境贵州、广州业务模块。
    - CPU限流/内存容量/Pod负载不均衡：Prometheus支持`avg_over_time`实现持续时长判断，指标成熟。
    - OOM风险：OOM事件指标 + Pod重启指标组合判定。
    - 省节点亲和性风险：`kube_pod_info`获取Pod归属Node，统计同Deployment下Pod宿主机分布情况。
    - 扩容容量风险：读取HPA指标，对比当前副本与最大副本，结合负载指标判断。
2. **外部数据源具备访问能力**
    - CMDB接口：完成业务模块与K8s资源映射，实现从业务视角输出风险，而非单纯K8s资源视角；
    - Pinpoint提供开放REST API，可拉取链路拓扑、调用指标；
    - 智能体平台内置定时调度能力，支持每日定时触发任务，执行风险计算并输出日志。
3. **输出物实现简单**
    采用结构化JSON日志，支持落盘存储，也可对接平台日志组件，方便后续检索、审计。

### 2.2 ⚠️ 现存难点与风险约束
1. **持续时长条件（持续15min）离线日度分析成本较高**
    Prometheus瞬时查询只能获取当前指标；每日离线任务需要判断**连续15分钟持续超标**，瞬时值容易误报。
    - 方案1：Range查询拉取24h时序数据，程序内滑动窗口校验；消耗Prometheus查询资源；
    - 方案2：预先在Prometheus配置告警规则，持久化告警状态，每日任务读取告警记录（推荐，降低智能体计算压力）。

2. **Pinpoint链路依赖分析开发成本高**
    链路拓扑、循环依赖、集中依赖**无标准Prometheus指标**，需要调用Pinpoint REST API，自行开发拓扑解析与业务规则。
    > 建议：仅筛选贵州、广州中心模块对应的服务，减少接口拉取数据量，降低Pinpoint服务压力。

3. **模块映射强依赖CMDB接口稳定性**
    CMDB接口故障/数据缺失时，无法将风险归属到业务模块。
    > 降级策略：CMDB不可用时，保留deployment原始信息，标记模块为【未知】，不中断整体日志生成。

4. **省节点亲和性风险区分困难**
    指标只能看到Pod调度结果（落在哪些宿主机），**无法直接区分是人为配置亲和策略，还是调度器随机调度巧合**。需要结合`kube_pod_spec_affinity`指标判断是否配置亲和策略。

5. **扩容容量风险规则定义不完善**
    “业务负载持续偏高”缺少明确阈值；业务QPS、连接数等业务指标依赖应用埋点。
    > 降级方案：业务指标缺失时，退而使用CPU/内存资源负载作为判断依据。

6. **日志管理需要配套策略**
    - 日志滚动：每日单独生成一份日志，需要配置历史日志清理策略，防止磁盘膨胀；
    - 风险去重：同一风险多天持续存在，需要生成风险指纹做去重标记；
    - 风险分级：当前方案缺少P0/P1/P2风险等级规范，需要补充定义。

## 3 总体可行性结论
> **整体评估：方案可行，中等开发工作量；K8s资源类风险可快速落地；Pinpoint链路分析工作量大，建议二期迭代。**
1. **一期（高可行性，优先开发）**
单点部署风险、CPU限流风险、内存容量风险、Pod负载不均衡、OOM风险、省节点宿主机亲和性校验、HPA扩容容量风险（基于CPU/内存负载）。
> 数据源：Prometheus + CMDB；暂不接入Pinpoint。

2. **二期（中等~高成本迭代）**
接入Pinpoint，实现链路依赖风险识别：集中依赖、下游依赖过多、长调用链、循环依赖、异常慢调用识别。

## 4 落地实施建议（分两期）
### 一期：K8s资源架构风险识别（交付目标：每日定时输出风险日志）
1. 数据源：Prometheus、CMDB接口；暂不接入Pinpoint；
2. 风险识别能力：
    - 单点部署风险
    - CPU限流风险（>20%，持续15min）
    - 内存容量风险（>85%，持续15min）
    - Pod负载不均衡（max/avg>2，持续15min）
    - OOM稳定性风险
    - 省节点Pod宿主机集中亲和风险
    - HPA扩容容量风险（基于CPU/内存负载）
3. 调度方式：智能体平台定时任务，每日凌晨执行；
4. 核心逻辑：拉取时序指标，程序内滑动窗口校验持续阈值；调用CMDB做模块映射；输出结构化日志文件。

### 二期：链路依赖风险识别扩展
1. 封装Pinpoint开放API，拉取服务调用拓扑；
2. 开发拓扑分析规则：识别集中依赖、循环依赖、长调用链、慢调用；
3. 将链路风险合并输出到每日架构风险日志。

## 5 风险规避建议
1. Prometheus查询优化：按cmdb_node过滤deployment，缩小查询范围；优先复用Prometheus告警状态判断持续时间，降低智能体计算压力；
2. CMDB接口增加降级逻辑，保障任务不中断；
3. 完善阈值与规范：补充扩容风险负载阈值，定义高危/中危/低危风险分级标准；
4. 日志优化：增加风险指纹实现风险去重，配置日志滚动、自动清理策略，防止磁盘占用过高。
